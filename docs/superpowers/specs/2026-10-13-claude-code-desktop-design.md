# Claude Code 与 Claude Desktop Code 适配规格和任务计划

日期：2026-10-13（北京时间）  
源码基线：桌面版本 0.3.9；思考强度修复提交 `1c90320`。  
状态：用户已明确授权按本规格实现 Mac 与 Windows 适配，版本保持 0.3.9；实现、限定范围代码审查和 Mac／Windows 开发打包已完成；以本地 Git 提交交付，未推送或发布。D1—D4 已确认。

本文规定如何将 Claude Code 终端与 Claude Desktop 的本地 Code 会话接入 Codexio，支持第三方 API 的 Token 用量和请求日志。客户端切换仅作用于概览、日志、用量；Claude 侧不接订阅额度，不进行费用计价，不提供执行行程。小猫报告按钮始终显示，报告只使用 Codex 数据；Mac 菜单栏和 Widget 继续使用 Codex 数据。

## 2 已确认范围

### 2.1 目标

用户主要通过第三方 API 使用 Claude Code，希望在同一个 Codexio 中查看 Claude Code 与 Claude Desktop Code 的对话、用户请求和 Token 用量。无需复制 OpenAI 的订阅、5 小时额度或周额度功能，也不要求为第三方模型制定价格。

首轮覆盖 Mac 与 Windows。iOS 不新增 Claude 界面或同步协议，Mac 菜单栏与四个 Widget 不随页面来源切换。桌面版本保持 0.3.9，未获新授权不得调整版本、推送或发布。

### 2.2 界面入口和作用域

1. 在概览上方现有小猫报告按钮旁放置 ChatGPT 与 Claude Code 的 Logo 切换入口，沿用现有应用的尺寸、主题和交互风格，不改 Codexio 品牌素材的画布中心。
2. 三个页面共享所选客户端来源：概览、日志、用量。来源切换不得混合 Codex 与 Claude 的统计。
3. 非适用页面继续使用其原有 Codex 数据，不让 Claude 选择改变订阅、价格、套餐历史、上游检测或账户行为。界面不得将这些页面误呈现为 Claude 功能。
4. Claude Code 终端与 Desktop 本地 Code 归入同一个 Claude Code 入口。内部保留可验证的终端／Desktop 来源标识；来源无法确定时留空，不假定缺少 Desktop 标记就一定是终端。
5. 客户端来源由采集来源与记录结构判定，不由模型名或 `provider` 判定。通过 Claude Code 调用 GPT、Gemini 的记录仍属于 Claude Code。
6. 不另建 Claude 订阅页、账号登录流程、价格页或执行行程页。未明确要求的额外入口、用户选项、服务或功能，发现确有必要时先停下询问。
7. 小猫报告按钮不随客户端选择隐藏或禁用，始终打开现有 Codex 报告。报告的数据、计价、预览、导出和缓存继续使用 Codex 作用域。
8. 每次主 App 重新启动时，客户端选择初始化为 ChatGPT／Codex，不持久化恢复上次的 Claude 选择。关闭主窗口而主 App 仍在运行不属于重启，当次运行中三页继续共享选择；这个启动规则不清空已经采集的 Claude 历史。

### 2.3 排除项

- Claude Desktop 普通 Chat、Cowork、未落盘的 side chat，以及仅存在云端或 SSH 远端的会话，不宣称已被本机采集覆盖。
- 不新增 Claude 周额度、5 小时额度、套餐历史、第三方余额查询、Claude 费用规则、Fast／Ultra Fast 换算或计价倍率。
- 本轮忽略 Claude 日志目录迁移，不新增目录选择、任意新路径自动探测或跨根历史迁移功能。
- 不接管 Claude 进程，不改 API 配置、凭据、日志保留设置或真实会话文件，不为获取数据启动客户端或发出模型请求。
- 不在首轮自行开启 OpenTelemetry、注入 hooks、添加独立后台常驻服务、增加代理转发或远端采集入口。
- 不扩充测试套件或三项打包冒烟，不新增维护性测试文件、pytest、全量回归、界面遍历或截图矩阵。

## 3 数据证据和可用边界

### 3.1 本机只读核查

2026-10-13 的 Windows 只读样本：

- `%USERPROFILE%\.claude\projects` 下有 40 份 JSONL，约 30 MB，包含主会话和子代理文件。
- 当前 Desktop 第三方模式的记录带有 `entrypoint: claude-desktop-3p`，记录版本为 `2.1.295`。Desktop 内置 Claude Code 与独立终端安装版本分开，不能只凭终端版本决定 Desktop 解析方式。
- 记录包含用户输入、回复、工具结果、`custom-title`、`cwd`、会话和消息身份、父消息关系、`requestedModel`、`message.model`、`effort` 与 usage 分项。
- 样本中的返回模型标识包含 Gemini 和 GPT，因此客户端分类必须独立于模型。
- 1,151 条 assistant 行仅包含 356 个不同 `message.id`；97 个 ID 跨文件重复。部分同 ID 记录先写全零 usage，后续才写最终计量。
- `.claude\sessions` 的会话元数据含进程身份、会话 ID、入口、当前状态与状态更新时间，可以作为该版本的当前运行状态证据。

用户随后在 Mac 安装 CLI 与 Desktop 并产生对话后，2026-10-13 重新只读核查到：

- `~/.claude/projects` 中有 2 份真实 JSONL，合计约 0.5 MB，分别来自终端和 Desktop 本地 Code；不是以 Windows 样本代替 Mac 验证。
- CLI 记录版本为 `2.1.296`，入口为 `cli`；Desktop 底层记录版本为 `2.1.295`，入口为 `claude-desktop-3p`。Desktop App 版本为 `2.31226.1`，与底层 CLI 版本分开。
- 两种记录均有人工消息身份、消息链、请求模型、返回模型标识、英文思考强度、输入／输出／缓存分项；CLI 样本还包含工具结果和非零缓存读取。
- 两种记录均存在一条 API 回复拆成多行的情况，仍需按真实回复身份去重。
- 样本包含 `isApiErrorMessage`、HTTP 错误状态和模型为 `<synthetic>` 的合成错误消息。它们可保留请求失败证据，但不能当成拥有真实 usage 的成功模型调用。
- CLI 的 `system` 记录提供 `subtype: turn_duration` 和 `durationMs`，可通过消息链核对到对应用户轮次。它是请求轮次级耗时，不是单个 API 调用耗时；归属和结束状态明确时，可支持该请求的耗时与平均 TPS。
- 本次 Desktop 样本只有 stop hook 与累计摘要等记录，未发现同等的明确轮次耗时；两种样本都未发现可直接使用的 TTFT 字段。缺值仍按规格显示 `—`。

这些数字是调查时的样本规模，不是持续采集结果。本文不保存对话正文、API 凭据或其他敏感配置值。

### 3.2 默认来源与发现

Claude Code 默认完整会话路径为 `~/.claude/projects/<project>/<session>.jsonl`，Windows 的 `~` 对应 `%USERPROFILE%`。子代理 transcript 位于该会话的 `subagents` 目录。显式配置 `CLAUDE_CONFIG_DIR` 时，根目录随之改变。[官方目录说明](https://code.claude.com/docs/en/claude-directory#application-data)

采集读取启动时已明确找到的 Claude 配置根：Codexio 自身进程存在 `CLAUDE_CONFIG_DIR` 时使用该路径，否则使用默认 `.claude`。给 Claude Code 单独设置的环境变量不会自动传给 Codexio；本轮不处理目录迁移，遵循 D4。用户当前 Mac CLI、Mac Desktop 第三方模式与 Windows Desktop 第三方模式均实际写入各自的上述 projects 目录；不能据此承诺所有 Desktop 版本、安装方式或运行模式都使用同一目录。对其他 Desktop 根，只接受经核查确为 Code transcript 的来源，不将 Electron 存储、普通 Chat 缓存或 Cowork 目录全部导入。

`history.jsonl` 是输入历史，不能单独充当 API 调用或 Token 账本；`stats-cache.json`、`cost-state` 等累计摘要不能与逐调用计量重复相加。优先读取完整 JSONL，详情通过索引的位置按需恢复。

如果后续实现发现 Desktop Code 不在已核验的可读来源中、需要新增用户设置或需要读取远端数据，应说明实际缺口并先询问用户，而非自行改变功能范围。

### 3.3 格式与历史完整性

官方明确 transcript 为内部格式，会随版本变化。适配器须容错、保存可用证据，并对缺字段降级，不能把当前样本字段宣称为永久公共协议。[官方格式边界](https://code.claude.com/docs/en/monitoring-usage#event-correlation-attributes)

CLI 默认具有年龄清理机制；新版本 Desktop 会话另有保留规则。没有采集过的已删除历史、未落盘或禁用持久化的历史无法恢复。按 D2，Codexio 已采集的统计和请求摘要持续保留，已删除的原始正文／附件显示缺失；不改 Claude 的清理配置。

Desktop 第三方模式支持兼容网关，历史保存在设备；SSH 模式的历史在远端宿主。Desktop side chat 不保存到磁盘。[第三方模式说明](https://claude.com/docs/third-party/claude-desktop/overview)、[Desktop 会话说明](https://code.claude.com/docs/en/desktop)

## 5 统一数据口径

### 5.1 客户端与来源身份

新增客户端类别与现有来源身份分开。当前 `source_id=local` 代表本机来源，并不代表“Codex 客户端”，不能用它区分 Claude。

建议规范字段：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `client_kind` | `codex` 或 `claude_code` | 旧 Codex 数据缺字段时兼容为 Codex；所有消费端必须限定客户端 |
| `client_origin` | 已核验的终端／Desktop 等入口 | 可空，不依据模型或缺少标记猜测 |
| `source_id`／根身份 | 本机、来源根与采集归属 | 保留现有语义，客户端类别另存 |
| `session_id` | Claude 会话身份 | 用客户端命名空间防止与 Codex 冲突 |
| `request_id` | 人工主请求身份 | 依据明确消息／prompt 与会话关联，不用正文相似或时间相邻合并 |
| `response_id` | 单次 API 回复身份 | 依据 `message.id` 等明确证据，用于同一回复更新和去重 |
| `requested_model` | 请求配置中的模型 | 以该请求自己的记录为证据，缺失不读当前设置回填 |
| 返回模型标识 | `message.model` | 保存原始标签，不套供应商真实性判断 |
| 来源位置与关系 | 文件、记录定位、父消息／子代理关系 | 供有界详情恢复与关联，不保留整份原文在全局 UI 快照 |

具体字段名、SQLite 索引与迁移方式可沿用现有实现，客户端身份及隔离约束不可省略。去重身份应结合明确 API 回复、消息链与来源证据，不能仅凭任意第三方网关 ID 跨无关记录合并。

### 5.2 Token

Claude／Anthropic 兼容格式的普通输入不包含缓存读取与创建。规范输入与总量为：

```text
input_tokens = raw_input_tokens + raw_cache_read_tokens + raw_cache_creation_tokens
total_tokens = input_tokens + output_tokens
```

推理 Token 是输出的细分，不第二次加进总量；缓存创建的 5 分钟／1 小时细分不与缓存创建总值重复相加。[官方 Token 口径](https://code.claude.com/docs/en/monitoring-usage#map-input-tokens-to-opentelemetry-genai-semantic-conventions)、[官方 Usage 类型](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/usage.py)

字段不存在与字段明确为 0 分开处理。不完整记录保留实际提供的分项；没有足够证据的完整输入、总量或命中率显示缺失，不能把未知缓存默认为 0 后宣称总量完整。供应商若另提供总量，必须先核对其分项语义和一致性，不能不经核对套用上述公式。

### 5.3 API 回复合并和最终计量

- 同一次回复的多个 content block 合并为一个模型调用，不按 JSONL 行 UUID 累加 usage。
- 同 ID 后续出现完整终值时更新已索引调用；早期全零／未终止片段不能永久占住该调用的最终计量。
- 不能将同 ID 的所有数值逐项取最大值当作公共协议。选择依据为已核验版本的结束证据、完整性和来源关系；存在冲突时保留真实读取状态。
- 分支、续接、压缩或复制文件中的既有回复不得再次增加 Token；同时不能只统计当前可见主链而漏掉已经发生的调用。
- 子代理 Token 正常纳入有明确父请求关系的请求汇总；缺少明确关系时保留未归属或独立子代理记录，不猜测分摊。
- `cost-state`、累计模型用量、会话总耗时不能再叠加到逐调用账本。
- 合成错误消息不充当成功 API 回复计量。保留其明确错误信息和人工请求归属，不因合成回复的零 usage 或占位模型制造已计量模型调用。

### 5.4 人工主请求

优先使用已核验的人工来源、prompt 身份、消息链和轮次关系。工具结果、合成上下文、补充输入、摘要、同一消息的多种表示和子代理启动输入不能自动增加独立主请求。

恢复主消息、续接和子代理关联时复用现有“主消息拥有自己的请求”的原则。不能按相同正文、相邻时间、相同聊天名合并独立请求。聊天标题不能回填为请求摘要。

### 5.5 配置、费用和计时

主请求行使用请求自己的开始配置；子代理及后续调用配置保留在成员明细和分布统计中。已经保存的主请求思考强度不得被 `Max + High` 或 `Max + Medium` 的成员集合清掉。缺证据的配置不从当前账户或当前 settings 补给历史。

Claude 来源的费用为 null，展示为 `—`。即使返回模型名与 OpenAI 价格目录一致，也不进入 Codex 计价、认证／消费来源回退或速度倍率路径；`cost-state.totalCostUSD=0` 和未知模型成本不能当成实际费用。

小猫报告始终使用 Codex 数据，继续沿用 Codex 计价和费用显示。Claude 页面的费用缺值规则不应用到这个报告。

本轮速度展示及快速模式占比为 `—`。可以保留原始速度元数据供以后用户明确要求使用，但不映射为 Codex 的速度档位。

历史完成状态与当前状态分开。会话 `idle`、进程存在、assistant `end_turn` 或 stop hook 单项证据都不能自行证明所有历史用户请求完整结束。具体判定仅使用经核查的版本语义；无法判定时保留缺失。

TPS 必须有对应请求／调用的已完成状态、有效输出 Token 与实际正耗时；TTFT 必须有明确首 Token 计时。时间戳差、第一条完整 assistant、thinking 时长和会话累计 API 耗时均不能替代。官方遥测虽有明确计时字段，不代表普通历史 JSONL 默认拥有这些字段；首轮不擅自开启遥测。[官方计时说明](https://code.claude.com/docs/en/monitoring-usage)

已核验的 Mac CLI `turn_duration.durationMs` 只用于经消息链归属确认的用户轮次。请求级 TPS 使用该轮次去重后的输出总量与轮次实际耗时，遵守完成状态和正耗时条件；不得将同一个轮次时长分摊或复制给每个模型调用，也不得将失败轮次当作正常完成轮次计算 TPS。没有同等明确字段的 Desktop 历史继续显示缺失。

### 5.6 原始日志删除后的留存

Claude 自动清理或用户删除原始日志，不等于已发生的消费被撤销。保留已索引的计量、用户请求及其摘要，以及支撑统计所需的会话／请求／子代理关系、模型、时间和配置元数据；来源文件消失不得连带删掉这些账本记录、物化统计或排行数据。

来源存在性、计量事实和详情可用性分开保存。确认文件删除后，更新其来源可用性，停止读取不存在的文件；保留稳定的记录身份与去重关系。同一回复之后在续接、复制或重新出现的日志中被发现时，不得再次增加已经保留的 Token 或请求数。

完整正文和附件确实已经删除时，详情显示缺失，缺失值统一为 `—`；已采集摘要仍可用于请求列表和摘要查询，但不能冒充完整正文。相关详情／媒体缓存失效后，不得继续把已删除的原文或附件显示为完整可用，也不重新扫描备份来伪造恢复结果。

读取失败、暂时不可访问与确认删除仍需区分，都不能清空已经采集的历史统计。保留历史不要求把完整原文常驻内存：账本继续采用 SQLite、分页与有界缓存，不增加独立归档服务，不修改 Claude 自己的保留设置。

## 6 架构与实现复用

### 6.1 数据流

```text
本地 Claude Code / Desktop Code transcript
    → 主 App 内的独立只读 Claude 适配器
    → 带客户端身份、最终回复计量和请求关系的规范账本
    → 按客户端查询的概览 / 日志 / 用量投影

Codex 原有采集和账本
    → Codex 专属报告 / 菜单栏 / Widget / 订阅 / 移动同步等消费端
```

不直接把现有全局 `usage` 替换为用户正在查看的客户端。页面选择应限定投影和查询；Codex 专属服务明确读取 Codex 作用域。两来源共享主程序生命周期，不共享未经筛选的业务结果。

报告入口保持可见且固定读取 Codex；报告数据、计价、缓存及导出不依赖 Claude 页面选择。原始文件删除只改变对应来源／详情可用性，已采集 Claude 计量与请求摘要留在账本中，并遵守 §5.6 的重复发现规则。

### 6.3 性能、缓存与生命周期

文件、解析、数据库、来源发现和历史聚合全部在后台。文件不变不重读、不解码；目录不变复用清单；保留有界兜底发现新建、替换、截断、归档、删除及迟到记录。SQLite 变化同时考虑主文件与 WAL。

派生结果的依赖至少包含客户端、来源根、账本 generation、筛选、时区、必要时间边界以及实际适用的计价规则。无业务内容变化不全局发布 UI、不重载列表、不反复显示加载动画。来源切换不触发整份历史重扫，旧来源的异步结果不得覆盖新选择。

日志与聊天排行坚持分页；详情按需恢复。新 Claude 页面优先沿用 SQL 有界查询／物化索引，不借接入功能扩大 Mac 的全量 UI 快照。悬停只命中已有投影，不读取数据库或执行新聚合。

合并扫描和刷新触发，防止重入；新增适配器由主 App 管理，不建立独立保活进程。普通关窗按既有菜单栏生命周期处理，正常退出停止自有服务。不要为本轮功能调整 Widget UI、Bundle 或注册生命周期。
