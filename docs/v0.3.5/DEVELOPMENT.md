# v0.3.5 内存优化

用户在本轮明确指定 Mac v0.3.5，并在完成内存定位和方案讨论后授权开始优化。开发包和本地提交不等于正式发布。

## 实现范围

- 运行时 Dock 图标画布由 1024 点调整为 512 点，保留源图、9% 透明边距和原画布视觉中心。2× 显示下仍对应 1024 像素；外观图标选择及菜单栏图形不变。
- 报告数值使用直接内容替换，移除 `numericText` 滚动过渡及数值独立动画。保留卡片淡入、周期切换、三套样式、布局、字号、阴影及静态分享导出。
- `AsyncProjection` 取消旧任务后立即移除自身引用，当前任务完成时也移除引用。完成回调先核对 generation，旧任务不能清除新任务或覆盖新结果；仍保留现有 12 份有界结果缓存。
- Mac 版本按用户确认更新为 0.3.5；Windows 与 iOS 源码、版本不变。Widget UI、独立短版本与构建号、注册及宿主启动／退出流程不变。
- 本轮不调整计价、账本结构、SQLite 查询或价格规则，不增加测试文件、测试项或维护性测试套件。

## 参考与测量依据

- 当前 `Branding.swift` 的相同比例绘制机制；Apple `NSImageRep.size` 的点／像素定义。复用现有原生图标绘制，只修正运行时画布尺寸。
- 当前 `ReportArtwork.swift`、`UsageReportReader.swift`、`UsageReportController.swift`；复用已有卡片和资源降采样，不改变数据准备或分享计量口径。
- 当前 `Presentation.swift` 的 generation 门禁与有界缓存；沿用 v0.2.10 Worker 的按实际数据变化失效原则，不以减少内存为理由增加扫描或重算。
- 2026-09-30 对正式 0.3.4 进程进行只读对象图分析，另用同一份隔离 SQLite 副本（4,443 条调用、392 条请求）和优化编译的诊断副本对照；2× 显示倍率、主窗口 1100 × 820 点。未启动或重启用户安装的 App，未联网或修改真实 Codex 配置。
- 图标两块 CG Image 缓冲区合计由约 64 MiB 降到 16 MiB，单项物理占用下降约 48 MiB。
- 保持卡片布局和阴影，仅关闭数字滚动后，周期切换后的物理占用由约 281 MiB 降到 170 MiB；叠加图标候选后约 121 MiB，基础占用约 111 MiB。连续 60 次快速切换属于专项压力情形，不代表普通操作。
- 以上是修改前诊断副本的同条件证据，不是正式安装版升级后的实测承诺；对象图中两份旧快照的可独立释放容器约 6.8 MiB，实际物理页回收幅度未单独量化。
- 原始测量条件、调用栈摘要和对照数据保留在 `build/checks/memory-audit-20260930/`。
