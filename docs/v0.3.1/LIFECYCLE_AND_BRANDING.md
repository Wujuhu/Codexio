# v0.3.1 主程序生命周期、小组件接管与新 Logo

日期：2026-09-27。App 保持 **0.3.1**；Widget 构建号 **18**，短版本 **1.17**。

## 本轮用户要求

1. 数据采集、额度查询、上游转发随主程序存活；⌘Q 停止自有服务，小组件提示打开主程序。
2. 新版自动接管旧版小组件，清理旧服务、注册与相关运行文件，保持唯一稳定宿主。
3. 按用户参考图绘制猫形 C 的 SVG，保留白底黑图、黑底白图；App 图标使用浅色版，沿用参考图的视觉中心并保持足够占比。

## 生命周期

| 操作 | 行为 |
| --- | --- |
| 关闭主窗口／⌘W | 主程序继续运行，菜单栏与数据刷新继续工作，可重新打开窗口。 |
| ⌘Q／退出 Codexio | 恢复上游配置，停止主进程内转发；停止采集与定时器，关闭并等待自有 App Server 子进程；在快照写入队列尾部原子写入离线状态，通知 WidgetKit 后退出。 |
| 主程序已退出 | 四个 Widget 显示“打开 Codexio 主程序”，离线时间线 `.never`；不创建采集服务、不联网、不自行拉起主程序。 |
| 点击离线 Widget／自行打开 App | 打开主程序后重新发布存活状态，恢复小组件内容。 |
| 下载了更新后普通退出 | 保留下载包，不自动重开主程序；只有用户主动选择安装，才启用一次性更新交接程序。 |

删除了独立 WidgetService 与 LaunchAgent 创建逻辑。旧 `--widget-service`、`--widget-refresh`、`--upstream-helper`、`--upstream-proxy` 模式在新版中直接结束。新的上游转发使用主程序内的 NWListener，不再复制并运行常驻 CodexioRelay。旧转发进程在恢复其路由记录后按所属路径和 PID 清理。

普通退出和安装退出采用有序收尾；重复按退出不会跳过收尾步骤。进程锁设置 `O_CLOEXEC`，避免锁描述符继承到子进程。取消退出／更新准备失败后清除安装意图，并恢复可继续操作的上游协调状态。

WidgetKit 的渲染与展示进程由 macOS 管理，系统可能按需唤醒它读取离线提示；这不运行 Codexio 的采集或网络业务。更新时机也由系统安排。实现采用主程序准备快照、状态变化时 reload、离线 `.never` 的方式，参照 [Apple：Keeping a widget up to date](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date/) 与 [TimelineProvider](https://developer.apple.com/documentation/widgetkit/timelineprovider)。

## 接管与清理

沿用 `v0.2.10` 的 `macos_app_takeover.py` 和 `macos_widget_repair.py` 的稳定宿主、先注册后注销、文件身份识别与失败恢复机制。

1. 校验传入完整 App 的标识、版本、Widget 构建号和签名；同 App 版本也比较 Widget 构建号。
2. 接管与自动更新共用 `/Applications/.Codexio-update.lock`。
3. 卸载并删除旧 `com.wujuhu.codexio.widget-refresh` LaunchAgent，停止旧独立刷新服务；安装时请求旧主程序正常退出，再处理其扩展进程。
4. 暂存并校验新版，原子替换 `/Applications/Codexio.app`，保留回滚包。
5. 稳定宿主注册并选用当前扩展，核对注册路径、短版本与构建号；成功后注销其他路径。App／扩展 inode、大小和修改时间参与安装身份，处理同一路径仍加载旧代码的情况。
6. 清理 Codexio Widget 自己的缓存、非活动旧数据目录里的 Widget 快照／安装标记，以及确认可清理的接管备份。正在完成接管时的当前回滚包由安装方在确认启动后清理。

清理范围仅限 Codexio 所属的进程、LaunchAgent、Widget 注册和私有缓存／标记。用户数据、已发布历史包、其他应用及系统全局 WidgetKit 数据库不在清理范围内。

四个 kind 保持：`com.wujuhu.codexio.request`、`com.wujuhu.codexio.quota`、`com.wujuhu.codexio.quota.dual`、`com.wujuhu.codexio.quota.segmented`。在线时原请求小／中／大组件布局继续保留。

## 菜单栏字段、排序与实时预览

设置 → 菜单栏 → 显示内容提供六项：周额度、当前任务状态、今日总费用、今日总 Token、当前任务费用、当前任务 Token。默认选中并按“周额度 → 当前任务状态”排列。勾选添加、取消移除；拖动行末手柄排序，也可使用手柄菜单上移／下移；有恢复默认按钮。已选顺序保存在 `menu_bar_fields`，全部取消时显示品牌图标。

实时预览与实际菜单栏共用 `MenuBarField` 格式化、`MenuBarReadout` 和 `TaskStatusImageView`，显示当前数值与所选顺序，状态 SVG 位于状态字段对应的位置。圆角容器、系统字体和单色图标保持现有风格，不增加说明气泡。长组合在设置预览内可以横向滚动。

| 字段 | 数据口径 |
| --- | --- |
| 周额度 | 当前账户的周额度剩余百分比，遵守额度新鲜度。 |
| 当前任务状态 | 复用本机任务记录与运行状态有效期；存在运行中的本机主任务／子任务则显示点阵环与“运行中”，无运行任务则显示用户提供的完成勾选 SVG，无可见“已完成”文字。初次读取完成前使用占位，不把未知显示成完成。未产生 Token 的新任务也能识别。 |
| 今日费用／Token | 本机、当前系统时区的今日统计，费用按现有模型价格估算。 |
| 当前任务费用／Token | 与现有请求聚合口径一致，优先当前运行中的本机主请求，随后为最近主请求；无法归属正在运行任务的计量时显示占位，避免沿用上一个已完成任务的数字。 |

状态源文件直接保存在 `src/codexio/icons/task-status/`：运行中来自用户提供的 `C-dot-ring-SVG.zip`，完成来自 `menu-status-icons/completed.svg`，SVG 内容保持原样。运行中以 Core Animation 按原设计的 1.6 秒、8 步旋转；完成后停止动画并显示完成 SVG。系统减少动态效果启用时使用提供的静态环。

状态与金额更新复用既有本机扫描和快照发布，不另起任务状态轮询。菜单栏内容格式化后未变化时跳过重设；动画不调用数据层，设置修改也不重新应用同一个外观主题。

最小冒烟与单张页面预览使用同一生产可执行文件和资源的隔离宿主，采用独立 mock Bundle ID，不带 Widget 扩展和 URL 接管声明，避免系统把 mock 当成真实的小组件宿主。仍保持原有三项基本冒烟，不扩充测试项。

## 字标、设置分区与更新时间修订

- 主窗口左上角显示 C 形 Logo 接 `odexio`，透明模板与系统字体组成一个字标，Mac 间距 1 pt；完整产品名称、应用标识仍为 Codexio。
- 设置分区顺序为外观、数据、应用、菜单栏。菜单栏的总开关、六项字段、排序、恢复默认和实时预览集中在最后一页。
- 主窗口顶部、菜单面板和用量更新时间采用“上次更新：M.d HH:mm”；主窗口与菜单面板移除右上角刷新符号，主窗口手动刷新保留 ⌘R。
- 额度 Widget 使用固定更新时间，放不下时省略；不再显示相对秒数和更新时间旋转符号。请求小／中／大组件本来没有更新时间行，不额外增加，实际请求耗时继续保留。
- Windows 主窗口同步使用 Logo + odexio、数据分区名称和固定更新时间；macOS 菜单栏独立页属于 Mac 功能。
