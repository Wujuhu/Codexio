# v0.3.1 开发步骤与完成条件

> **实施前置条件**：用户已审阅 [总规划](PLAN.md)与[全区域视觉对照](VISUAL_SPEC.md)，明确表示整体设计满意且可以开始改代码。在此之前，本文件仅是后续执行顺序，不授权更改程序。v0.3.1 是目标版本；正式推送和发布另需用户开发验收后的第二次明确确认。

## 总顺序

```text
视觉稿定稿 → Swift 工程与旧数据兼容 → 额度／日志／费用核心
           → Codex／Claude 风格六页主界面 → Nowdex 风格菜单栏
           → 新额度小组件 + 原请求组件原样保留
           → 原生更新／稳定宿主接管／开发包
           → 一次基础冒烟与交付校验 → 本地提交 → 用户验收
```

每阶段只核对该阶段真实风险；不为日常修改新增测试文件或扩大测试范围。最终开发打包自带基础冒烟时不重复跑。

| 阶段 | 先做什么 | 产物／完成条件 | 不要带入的旧习惯 |
| --- | --- | --- | --- |
| 0. 设计冻结 | 用户逐页审阅六页、设置、菜单栏、三个新额度样式和明暗状态；按当前 Codex／Claude／Nowdex 实图修订 | 文档记录最终选型和对应参考图，用户明确允许开始实现 | 不拿早期 C/PySide6 视觉约束或被否定的草图当成新 Mac 规范 |
| 1. Swift 工程骨架 | 建立 Mac 主 App、共享状态模型、Widget 扩展、必要后台辅助程序的工程组织；确定版本号、Bundle ID、数据目录与打包路径 | 原生空壳可启动，菜单与 Dock 生命周期清楚；未来 Mac 包不内嵌 Python/Qt | 不直接把原 Python 窗口塞入 WebView 或只换 Swift 外壳 |
| 2. 旧数据兼容 | 梳理当前配置、价格目录、日志索引和 Widget 快照字段；实现只读旧数据／安全迁移 | 用户原有设置和索引可继续使用，失败可回退且不删除原文件 | 不以“全新大版本”为由清空本机历史 |
| 3. 额度与账户 | 移植 Codex 发现、`app-server` 连接、账户模式、五小时／周窗口、通知刷新和错误状态 | Swift 端能拿到与旧版同口径的额度；API／自定义 provider 模式显示不适用 | 不用本地 Token 推算官方余额，不在重置时刻伪造 100% |
| 4. 用量与价格 | 移植本机／SSH 增量扫描、去重、主请求与模型调用分组、已确认 Token、费用和估值 | 六页所需数据由同一 Swift 数据层提供；新旧统计口径一致 | 不双算缓存 Token，不把未知价格显示成 0 |
| 5. 主窗口 | 先按当前新版 Codex 完成原生外壳／侧栏／标题栏，再按设计稿完成概览、日志双模式、用量、订阅、定价、设置；Claude 负责详情与表单视觉基准 | 六页功能完整，点击式详情与简化文案可用；浅色／深色与收起侧栏一致 | 不复刻旧 Qt 的多层卡片、长注释和无意义悬停提示 |
| 6. 菜单栏 | 以 Nowdex #6 的面板视觉为直接样板，接入同一额度与今日／七日数据 | 关主窗口仍可查看；刷新、打开主窗口、设置、退出正确；无第二套采集器 | 不把 Nowdex 截图里的 Cursor/Grok 等服务新增到 Codexio |
| 7. Widget | 新增独立的额度专用最小组件，按 #1／#2／#5 完成三个可选样式；现有请求小／中／大只迁移宿主与数据接口 | 已安装的三个请求组件外观、内容顺序和 `kind` 不变；新组件能单独添加和读取额度 | 不顺手重排旧请求组件，也不让“无请求”挡住新额度组件显示 |
| 8. 生命周期与更新 | 移植后台刷新、唯一 `/Applications/Codexio.app` 宿主接管、原位更新与失败回滚；改造 Mac 构建脚本 | 签名、版本、Widget 构建号、ZIP、架构、清单和 SHA-256 校验通过；目标进程占用时保留旧包和新版暂存 | 不启动用户安装的 App，不覆盖运行中的包，不写入 `release` |
| 9. 最小验证与交付 | 使用现有隔离模拟冒烟，随后开发打包并本地提交 | 只核对能启动、基本数据显示正常、主窗口能关闭再打开；Mac 开发包在 `build/dev/macos`；本地 Git 提交 | 不维护 pytest、全量回归、额外 UI 遍历、截图矩阵或专项测试文件 |
| 10. 发布关口 | 用户完成开发包验收后另行明确确认发布及 v0.3.1 | 才按项目发布协调脚本推送、触发 Windows CI、生成三附件 Release 与正式归档 | 不把本地提交、开发包或设计通过当作发布授权 |

## 页面实施顺序与参考闭环

1. **共同外壳先定**：窗口比例、Codex 式侧栏、标题栏、按钮、明暗状态统一确定，六页复用。品牌区的图标和文字直接按最终参照稿放置，收起控件独立。
2. **概览与订阅先接额度**：以 Nowdex 参考图做额度表达，确认“已用”与“剩余”的文案和进度方向；两页用同一额度组件与状态模型。
3. **日志双模式与详情**：先保留现有搜索和过滤能力，再把悬停详情改为明确选择。数据源、实际模型、子代理归属和运行状态不能因视觉简化消失。
4. **用量与定价**：接入原有日期、粒度、模型和价格目录；颜色与图例沿视觉稿，未知值按原语义留空。
5. **设置与弹窗**：集中处理外观、数据源、应用、上游检测和更新；删除多余注释，必要说明就近可见。
6. **菜单栏与 Widget 最后共用稳定数据**：避免先做漂亮壳再临时另算数据；两者从同一 Swift 快照读值。

## 数据与交付边界

- Mac 与 Windows 在产品行为和数据口径上保持一致，但不强迫共用语言。Windows Python 代码不因 Mac UI 重构而被顺手改写。
- 旧请求 Widget 的 UI **不得变化**。在重构过程中若 SwiftUI 系统渲染与现有视觉略有差异，优先调整宿主或渲染兼容以恢复旧外观，而不是宣布新版设计。
- 新额度 Widget 小组件和菜单栏的刷新须遵循系统节奏；不能承诺逐秒实时。原始会话日志、Codex 凭据和系统 WidgetKit 数据库不被修改。
- 保留现有自动更新的 ZIP、稳定宿主、签名校验和失败回滚规则。开发包只放 `build`，正式发布仍使用同版本 Mac ZIP、Windows EXE 与一份合并 `latest.json`。

## 验证范围，保持最少

1. 开发阶段只针对实际改动做必要检查；发现具体问题才检查相关部分。
2. 最终开发打包时使用现有隔离模拟入口一次，固定检查：**能启动、基本数据显示正常、主窗口能关闭并重新打开**。
3. 版本、签名、Widget 构建号、归档完整性、文件大小与 SHA-256 是交付核验，不扩展成新的测试套件。
4. 不新增 pytest、测试数据、专项脚本、UI 遍历或截图矩阵。设计草图和真实参考图用于设计审阅，不作为自动化测试产物。
