# v0.3.1 macOS 原生重构与视觉设计规划

> 状态：设计规划草案，等待用户逐项审阅。目标版本为 **v0.3.1**；本阶段只产出设计与规划文档。项目当前的 `0.2.10` 程序版本、代码、构建产物和发布状态保持原样。只有用户明确表示整体设计满意、可以开始实现后，才进入代码阶段。

## 1. 这一版要达到的结果

将 **整个 macOS App** 迁移到 Swift，以 SwiftUI 构建主要界面，必要的窗口、菜单栏与系统生命周期由 AppKit 配合。最终 Mac 包不再依赖 Python、PySide6、Qt 或 PyInstaller。保留现有六个页面和已确认的数据口径，重新设计它们的视觉层级与交互；同时加入原生菜单栏面板及新的“只显示额度”的最小桌面小组件。Windows 端继续使用现有实现和既有发布流程。

设计目标是安静、清楚、精致的 Mac 数据工作台：一眼读懂额度，需要分析时仍能进入完整数据。ChatGPT、Claude 的 Mac 客户端用于参考原生窗口、导航、留白与操作节奏；Nowdex 的附件用于参考额度卡片、进度表达和菜单栏信息结构。Codexio 保留自己的名称、Cobalt X 图标与数据语义，不直接复制其他产品的标识、素材或界面。

| 指定参考 | 在设计稿中重点比较 |
| --- | --- |
| ChatGPT for macOS | 原生标题栏与侧栏关系、窗口工具栏的收放、主要内容区的视觉聚焦和快捷入口 |
| Claude Desktop for macOS | 克制的文字层级、留白、设置与常用操作的可发现性、窗口内容的阅读节奏 |
| Nowdex（用户提供附件） | 大百分比与细进度、单／双额度卡、明暗样式配对、菜单栏窄面板的信息顺序 |

## 3. 视觉方向与组件原则

### 3.1 视觉基调

- **外壳**：遵循 macOS 原生窗口、工具栏、侧边栏、Popover、系统菜单与焦点行为。界面大框架维持“左侧导航 + 中央内容”，但减少多层套卡和重复描边。
- **颜色**：以温和的浅色和深石墨为基础，现有 Cobalt X 蓝色作为品牌点缀。额度、费用、Token、状态分别使用稳定的语义色；整页不因图表多而变得花哨。明暗模式的层级通过对比度和材质建立，不依赖大量阴影。
- **字体**：正文与数据优先使用 Mac 系统字体。产品名可设计独立字标，但须与 Cobalt X 图标协调，避免为了“艺术体”牺牲识别和中文环境下的整洁度。数字采用易比较的等宽数字样式。
- **节奏**：统一窗口内的边距、卡片圆角、行高、字号层级和控件间距。标题、关键数值、次要说明各有固定层级；紧凑与宽屏布局共享同一视觉规则。
- **图标与动效**：使用系统图标语言和少量品牌图形。动效只帮助表达展开、切页和状态变化，并服从系统“减少动态效果”设置。
- **可读性**：百分比、数据新鲜度和可用性不能只靠颜色传达。支持键盘、VoiceOver、系统缩放与高对比度；浅色、深色都必须可读。

### 3.2 左上角品牌区域，待设计稿比较

提出两版并在实际窗口中比较：

1. **A：字标为主（建议优先）**。左侧用克制的 `Codexio` 字标，Cobalt X 保留在 Dock、应用图标和菜单栏；收起侧栏按钮放到原生工具栏位置，与字标分开。窄侧栏只保留图标导航。
2. **B：图标与字标并列**。缩小图标的视觉重量、调整基线和字距，把收起按钮移出品牌行，形成清晰的三层关系。

两版都要避免当前“图标 + 名称 + 收起按钮”挤在同一条窄行里的拥挤感。最终选型由完整明暗设计稿决定；在此之前不改现有图标或产品名。

## 4. 主窗口信息架构

保留 **概览、日志、用量、订阅、定价、设置** 六页及当前数据口径。侧边栏保留展开／收起与已保存的导航顺序，窗口关闭后仍可从 Dock 或菜单栏打开。页面布局允许重新组织细节，已有过滤、查看与编辑能力应继续可发现、可操作。

| 页面 | 设计重点 | 必须保留的能力与状态 |
| --- | --- | --- |
| 概览 | 顶部以 5 小时、周额度为主角；Token 构成、今日核心数字和趋势按阅读顺序逐层展开；刷新时间放在容易找到但不抢视觉的位置 | 剩余百分比、重置时间、额度不适用／过期／读取失败、费用与 Token、请求数、缓存命中率、期间切换和图表 |
| 日志 | 搜索、筛选、表格与请求详情形成清晰主次；由**点击或键盘选择**查看详情，避免鼠标扫过时突然弹出大块信息 | 用户请求／模型调用切换、时间与来源筛选、选中保持、完整详情、复制、未定价和运行中状态 |
| 用量 | 将每日 Token 活动、汇总卡和趋势图整合为安静的分析页；图例、日期和模型筛选形成固定工具区 | 今日／近 7 天／近 30 天／历史、每日活动、图表、对比和数据缺口表达 |
| 订阅 | 额度大数字与周期信息优先，估值和历史记录次之；不同时间窗口在字级上分明 | 五小时与周额度、周期记录、重置时间、额度观测估值及其“估算／不可用”口径 |
| 定价 | 以清晰的模型价格表为主，编辑入口明显；降低密集描边和说明文字 | Standard、Fast、上下文条件、价格同步／手动编辑、未定价与参考估值状态 |
| 设置 | 采用 Mac 熟悉的分组设置结构，缩短表面说明；高风险或影响数据的开关仍说明后果 | 外观、数据源、本机／SSH、Codex 路径、刷新与估算、上游检测、自动更新、菜单栏选项 |

### 4.1 主窗口交互约定

- 原生菜单承担“设置、刷新、显示主界面、关闭窗口、退出”等系统级动作；保留现有 ⌘K、⌘,、⌘R、⌘W、⌘Q 的有效用途。
- 数据分析相关的提示通过明确标签、状态行、点击后的详情或信息按钮呈现。列表行不会因为轻微鼠标移动而遮挡内容。
- 窄窗口优先压缩次要列和间距，保留关键数值及其标签；需要详情时进入检查面板或独立详情视图，不让文字只剩省略号。
- 系统外观切换、窗口大小、侧栏状态、筛选与当前页面的恢复行为在设计稿中明确，避免实现时临时决定。

## 5. 新增“只显示额度”的最小 Mac 小组件

新增独立的 **Codexio 额度** 小组件，目标尺寸为 WidgetKit 的 `.systemSmall`。已有 **Codexio 请求** 小、中、大组件及其已添加实例继续保留；新组件不以同名同 `kind` 覆盖原组件。额度小组件即使没有最近请求，也应能独立显示可用的额度快照。

| 拟交付样式 | 内容和层级 | 对应参考 |
| --- | --- | --- |
| A 聚焦 | 用户选“5 小时”或“周”；醒目显示一个**剩余百分比**，一条连续进度、重置时间、数据更新时间 | #1、#4 |
| B 双额度 | 同卡上下两行显示 5 小时与周额度；每行百分比、简短进度、重置时间；两行仍能一眼比较 | #2、#3 |
| C 刻度 | 与 B 相同的数据范围，以节制的细刻度进度替代连续进度；更强调图形节奏 | #3、#5 |

三种样式均作为 v0.3.1 的设计与交付目标，各制作浅色、深色设计稿；可讨论是否再提供“跟随系统／固定浅色／固定深色”的组件配置。若 Mac 桌面系统对某种外观的呈现限制视觉效果，应优先保证文字对比与信息完整。默认推荐 B；A 适合只关注一个额度的人，C 适合偏好刻度图形的人。样式细节、名称和默认值由设计审阅确定。

**数据规则**：所有大数字明确标“剩余”，进度方向与数字一致；5 小时与周额度沿用当前同一 `app-server` 数据源。无额度、API Key／自定义 provider、不适用、缓存、读取失败或过期时显示对应状态和 `—`，不把未知值变成 0% 或按重置时间自行伪造 100%。本地时间显示重置时间，系统允许时显示更新时间；WidgetKit 决定最终刷新时机，界面不得暗示实时更新。卡片不显示请求文本、费用或 Token。若“重置次数”没有可靠且适合当前账户的现成数据，不为模仿参考图加入该字段。

## 6. 原生菜单栏面板

菜单栏图标点击后打开原生 Popover 风格的窄面板，作为“快速看一眼”的入口；它不是第七个完整页面。建议内容从上到下为：

1. **顶栏**：Codexio 名称、最近更新时间、手动刷新；“打开主界面”有明确入口。
2. **额度卡**：5 小时与周额度的剩余百分比、进度和重置时间；错误或不适用状态原样表达。
3. **今日摘要**：已确认的 Token、费用估值、请求数；费用注明属于估算的语义，不作为实际账单。
4. **最近 7 天**：简洁趋势图，仅在现有数据完整到足以表达时展示；没有可用数据时使用克制空态。
5. **底部操作**：设置、退出。更深的日志和用量分析引导到主窗口。

面板保持单一滚动区域和稳定宽度；不把参考图中 Codex、Cursor、Grok 等多个产品当成新接入需求。菜单栏图标使用适应明暗菜单栏的单色图形；可在设计稿中比较“仅图标”和“图标 + 周剩余百分比”，后者在数据不可用时自动退回仅图标。菜单栏默认显示，设置中提供显示开关。关闭主窗口后后台采集和菜单栏仍运行；退出 App 才停止。点击外部或按 Esc 收起面板，刷新与主窗口使用同一份状态和刷新任务，避免重复轮询。

## 7. 文案、注释与悬浮提示清理

这里同时处理两类可能的“注释”：界面里冗长的辅助文案，以及未来重构时源码中仅重复字面意思的注释。优先清理用户可见的噪声。

- 删除重复标题含义、解释显而易见操作、常驻占空间却不帮助判断的说明文字；把必要的长说明放进设置详情或帮助入口。
- 对“费用是估值”“额度数据过期”“价格缺失”“API 模式无 ChatGPT 额度”等会影响理解的事实，保留短而直接的可见状态，不能随着装饰性说明一并删掉。
- 悬浮提示仅用于被截断的完整值、难以常驻显示的精确时间、必要的图表数据点，或已有控制在无文字状态下的解释。普通按钮和表格不叠加重复提示。日志详情不依赖悬停。
- 鼠标悬浮、键盘焦点与 VoiceOver 的信息一致；清理悬浮提示时保留可访问名称。源码中只保留解释边界条件、数据口径、安全迁移和系统行为的注释。

## 8. 设计交付顺序与停止线

1. **方向稿**：用这一规划确认范围、参考图解释、品牌区域 A/B 和小组件 A/B/C 的方向。
2. **完整布局稿**：六页的主要宽度与侧栏状态、菜单栏面板、小组件样式；先确定信息层级、内容密度与关键交互。
3. **视觉定稿**：系统浅色和深色的主窗口、菜单栏与小组件；包含加载、无数据、过期／错误、额度不适用、部分未定价等关键状态，完成文案与悬浮提示审阅。
4. **用户审阅**：记录反馈并改设计文档和设计稿，直到用户明确表示整体设计满意。设计决定冻结后才拆分实现任务。
5. **代码阶段**：只有收到用户明确的“可以开始实现”后才启动 Swift 迁移；随后按 [实施注意事项](NOTES.md) 保持数据、更新和发布链路的一致性。

本规划文件是**设计讨论起点**，不是最终视觉定稿，也不构成代码实施授权。开发打包与正式发布是更后面的独立关口；正式推送、Tag 和 Release 仍需用户另行明确授权。

## 9. 设计验收标准

- 六个现有页面的入口、核心指标和关键操作在设计稿中都有确定位置；页面看起来属于同一套 Mac App。
- 左上角品牌、侧栏收起控件、窗口工具栏不再相互挤占；用户可直接比较 A/B 方案。
- 额度小组件有多种可区分的样式，至少一个样式能同时清楚显示 5 小时与周额度；浅色、深色及未知状态都可读。
- 菜单栏面板能在一眼之内找到额度，今日用量和趋势不会压过额度；所有数字与主窗口口径一致。
- 非必要说明和悬浮提示显著减少；必要状态与精确数据仍可找到。
- 用户完成整套设计审阅并明确同意后，才允许进入代码修改。
