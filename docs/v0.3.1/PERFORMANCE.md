# v0.3.1 实际数据性能与交互修复

日期：2026-09-27。处理用户反馈的卡顿、高能耗、字段显示、订阅资料、更新入口、侧栏与小组件注册方式。App 版本保持 0.3.1；Widget 构建号 16、短版本 1.15。

## 卡顿与高能耗的证据

对用户已运行的 Codexio 做只读进程采样，没有重启该进程。采样前 CPU 约 98.5%；数据队列的主要采样都落在 UsageRow.date、parsedDate 和 ISO8601DateFormatter 的反复创建／解析。旧版视图的计算属性还会在主线程重复筛选整份账本、生成趋势桶，并为每一条详情扫描完整调用列表。

此前少量 mock 的三项基础冒烟没有验证这些数据规模下的开销。这次直接针对已经出现的问题测量和修复，不把原生技术栈等同于性能已经达标。

## 性能改动

- 每条 UsageRow 在构造时解析一次时间；日期解析、输出格式器按线程复用，已解析的时间字符串有界缓存。
- 定价按模型建立索引，避免每条调用都线性查找整张价格表。
- 统计和筛选在独立后台队列计算；概览、趋势、日志使用有界查询缓存，过时结果不会覆盖新选择。
- 详情按调用 ID 索引查找，取消逐行扫描全部历史调用。
- 账本没有变化时不重新发布整个 UI 快照；扫描时间由独立的小状态对象刷新。
- 日期／模型／档位／搜索改变时只更新对应结果；日志保持分页、原生表格只创建可见单元格。
- Widget JSON 写入和刷新移到后台；数据未变化时使用五分钟保活，不因刷新时间改变而每分钟重绘所有组件。
- 日志文件的大小与修改时间未变化时跳过游标解码；会话标题限频读取。定时器加入合并唤醒容差。
- 主窗口不可见时暂停套餐历史和聊天明细轮询；进行中耗时只更新可见表格中的对应单元格。

## 与问题直接相关的测量

测量只读取现有索引，不联网、不写回用户数据库。计时属于定位本次性能问题的一次性检查，不新增测试套件或基础冒烟项目。

| 测量 | 结果 |
| --- | --- |
| 同批 2,407 条时间记录解析三轮，原实现 | 3,426.98 ms |
| 相同记录和结果，新解析器 | 272.67 ms，约快 12.57 倍 |
| 2,415 条本地记录生成完整统计快照 | 733.87 ms，在后台完成 |
| 今日趋势查询 | 2.82 ms |
| 七天／三十天／全部趋势查询 | 38.86／42.80／46.86 ms |
| 日志首屏分页查询 | 0.06 ms |

这些是热点和数据计算计时，不是整个 App 的帧率或功耗倍数。后续交互反馈已确认来自与开发包相同的安装版；该进程一次只读观察约 1.3% CPU。CPU 热点下降不代表点击和拖动问题已经解决，以下继续记录交互修复。

## 功能与界面修复

1. **Credits**：0E-10 表示精度为十位小数的零；规范显示为 0。列名明确为“已用 Credits”，与每周限额占比分开。
2. **周额度估算**：标题简化为“周额度估算”，默认展开。
3. **订阅资料**：没有手填套餐名称时自动显示当前账户套餐和邮箱。当前 App Server 的 Account 合同只提供邮箱和 planType，没有订阅价格／续费日期；保留已填写值，缺失时明确显示“未提供”，允许手动补充。
4. **原生表格**：定价与日志采用 AppKit 表格，表头和数字使用一致对齐；限制列宽和弹性范围，避免列间过大空白或自动滚动到被截断的模型名。
5. **日志字段**：默认保留请求／时间、模型、输入、输出、缓存命中率、费用、耗时、详情；当页“显示字段”菜单可选择总 Token、缓存读写、推理强度、速度、上下文、状态等字段，保存选择并可恢复默认。来源列继续删除。
6. **更新与版本**：“当前版本 · Codexio 0.3.1”和“检查更新”放在设置应用页顶部；手动更新独立于自动下载开关。
7. **侧栏**：恢复拖动边界调整宽度，拖窄自动收为图标栏；保存展开宽度与折叠状态，兼容旧版宽度偏好。
8. **菜单栏**：删除最底部“打开主界面／设置／退出”整行，保留顶部 Codexio 入口。
9. **额度 Widget**：三种样式分别注册为独立 StaticConfiguration，无样式切换和编辑配置：

| 独立组件 | kind |
| --- | --- |
| Codex 单额度（周） | com.wujuhu.codexio.quota |
| Codex 双额度 | com.wujuhu.codexio.quota.dual |
| Codex 刻度额度 | com.wujuhu.codexio.quota.segmented |

原请求 Widget 的 kind 和小／中／大布局继续保持。后续新样式独立注册的规则已写入 AGENTS.md。

## 第二轮：列宽、侧栏闪动与导航漏点

用户反馈：定价、用量表格表头与值全部居中，每列可拖动调整；侧栏拖动闪动；导航需要重复点击。

### 原因与实现

- 旧侧栏在移动的拖柄上使用局部拖拽坐标，边界本身移动后坐标产生反馈；同一次拖动还会反复切换 140 pt 展开栏和 62 pt 图标栏。新拖柄使用固定屏幕坐标，拖动中只调整侧栏局部预览宽度，松手后才保存全局宽度、决定是否收起。游标使用 AppKit cursor rect，不再反复 push/pop。
- 原导航的整行同时绑定 Button 与 onDrag，透明空白区域没有完整点击命中形状。新导航使用覆盖整行的原生按钮，接受非活动窗口的首次点击，按下即选择页面。排序拖拽移到行末独立手柄，保留原图标和拖动排序能力。
- 定价使用 NSTableView 原生列边界拖动；所有表头与单元格居中。原先固定的最小／最大列宽改为可调整范围，用户选择覆盖自动分配值，刷新或重建页面时仍保留。日志也复用列宽保存能力，原字段选择、末列详情悬停继续保留。
- 用量的聊天排行与本机 Token 排行保持原展开详情布局，表头、聊天名称、数值居中；表头两列之间的边界可拖动，在相邻列之间分配宽度。两种排行分别保存列宽。模型／速度／推理强度展开详情仍保留。
- Mac 列宽保存在隔离感知的 Preferences 下，键为 `native_table_widths`，不用共享的 NSUserDefaults 自动保存。拖动宽度不重新启动数据定时器，也不触发账户查询。
- Windows 定价、聊天排行同步使用居中对齐和 Interactive 列宽；刷新不覆盖手动宽度，列宽进入既有页面状态保存机制。此轮 Windows 做语法核对，正式 Windows 构建仍在用户确认发布后由 CI 完成。

### 验证范围

仅对上述实际问题做一次性隔离交互核对，未增加测试文件、维护测试入口或扩大三项基础冒烟。当前开发包的三项基础冒烟、签名、版本、ZIP 解压完整性和清单校验通过。仅导出一张生产视图的定价 mock 图查看居中与列间距。

- 向隔离 AppKit 窗口发送单次点击，命中导航行空白区域后立即选中定价、用量页；事件派发约 0.71／1.13 ms。这是事件处理耗时，不是全页面渲染或真实账户查询耗时。
- 侧栏连续拖动 +20／+60／−30 pt，实际边界位移一一对应；拖动期间未发布全局宽度，也未切换展开状态。松手收起和再次松手展开只产生 `[false, true]` 两次状态变化，保存的展开宽度为 222 pt。
- 定价模型列调整到 283.5 pt 后，数据刷新及页面往返均保持；聊天排行周额度列调整到 150 pt 并写入偏好。
