# v0.3.1 二次复查与验收图

日期：2026-09-27。用户要求再次检查实现是否符合全部要求及规划，发现问题继续修复，并提供覆盖各功能的 mock 验收截图。本次据此导出当前实现的验收图；这不是新增的自动回归截图矩阵。

## 本次发现并修复

| 问题 | 修复 |
| --- | --- |
| 概览选择“今日”时，趋势仍固定取最近七天；最近请求也未跟随日期范围 | 曲线按当前范围分桶，今日按小时，历史按周；最近主请求同步遵守日期范围 |
| Mac 重置提交前只比对凭据，未重新读取所选券与服务端账户 | 重新读取包含明细的额度，核对 `accountId` 与前后身份；首次提交重新验证所选券，重试继续使用原幂等键 |
| Mac 额度读取期间换账户可能给旧响应附上新身份 | 读取前后核对身份与服务端账户；不一致时关闭旧连接并拒绝旧响应 |
| 新额度 Widget 可能把本地日志更新时间当额度新鲜度，失败时仍带旧重置次数 | 快照增加独立额度时间；失败时不发布旧次数，新组件对未知／过期保留空值 |
| 最小非零额度四舍五入后可能显示 0%；刻度样式缺少“剩余”语义 | 新额度 Widget 显示 `<1%`；两组刻度显式标注剩余，暖色双额度默认黑底 |
| 年热力图仅显示起止月份，未对齐图 5 的月度导航 | 添加全年月份轴，并预留悬停信息高度，避免内容跳动 |
| Windows 聊天排行没有展示 `partial`／`unavailable` 状态 | 行标题显示部分数据／暂不可用；读取失败时保留统计时间并显示错误状态 |
| Windows 重置明细读取依赖接口默认值 | 显式请求 `excludeResetCreditDetails=false` |
| 原生定价页未遵守本机可选模型目录，缺少同步时间／冲突状态 | 使用可用模型目录筛选，保留缺目录时的价格回退，并显示同步时间和真实价格警告 |
| 上游检测缺少规划中的“现在重启／稍后自行重启” | 路由更改后对运行中的官方客户端提供选择，正常退出后才重开；恢复失败时显示保留记录或返回应用的选择 |
| 上游转发的重定向仅比较主机 | 同时核对协议、主机和端口，避免将认证请求转向不同源 |
| 较矮显示器上最小窗口高度可能超过可用区域 | 最小窗口尺寸同时受可用屏幕约束 |

主 App 版本保持 **0.3.1**。按照 Widget 更新约定，新组件显示逻辑与快照变化使 Widget 构建号递增为 **15**、短版本 **1.14**。

## 与用户要求逐项对应

- Mac 运行代码为 Swift／SwiftUI／AppKit，保留六页整体框架、旧导航图形、系统字体和较小额度字号。
- 日志末列详情使用临时浮层；用户请求和模型调用共享对应详情视图，无固定右侧面板。
- 菜单栏保留圆角分组，组名为 Codex，状态项可直接显示周或五小时剩余百分比；材质使用系统原生能力。
- 旧请求 Widget 三种尺寸的内容顺序、字号和布局保持；仅增加独立额度 Widget 的显示修正与隔离预览入口。
- 每张重置保留完整截止时间和行末按钮，确认后才使用所选 ID。真实消耗入口仍在 mock 模式下被阻断。
- 图 5 全部来自本机记录；图 6／7 使用独立的官方报告，缺失与真实零值分开。
- Mac／Windows 中英文与系统字体；两端 SSH 运行代码与来源入口已移除，仅保留旧键的兼容清理与历史账本。
- 原有参考图、设计稿和开发步骤保留在本地，当前验收图来自本次代码中的实际原生视图。

## 验收图的含义

验收图使用专用隔离 mock 账户、调用记录、额度和重置券，覆盖概览、日志及详情、活动、趋势、聊天排行、订阅、定价、设置三分区、菜单栏、新额度三样式、原请求三尺寸，并补充英文主界面。

- 主页面与 Widget 图从产品的 SwiftUI 视图直接渲染；Widget 预览只注入尺寸环境，不安装或改动用户的桌面小组件。
- 日志详情图将同一个详情视图置于展开位置，用于审阅内容与覆盖关系；生产交互仍由鼠标／键盘焦点控制原生 Popover。
- 菜单栏使用同一个原生菜单视图；背景为专用 mock 环境，实际透光与系统版本、背景和辅助功能偏好有关。
- 模拟环境阻断账户请求、真实重置、宿主接管、后台服务安装和上游配置写入。

## 核验范围

对照源代码、规划与实际 mock 图检查，继续使用固定三项基础冒烟；签名、Widget 版本、ZIP 和哈希属于交付核验。没有执行真实额度消耗、改写真实 Codex 配置或代用户启动安装版。Windows 的真实操作系统／正式 EXE 核验仍在确认发布后的 Windows CI。

此复查可以说明本次检查覆盖范围内的问题已经修正，不能等同于保证任意环境绝无缺陷。真实账户的额度服务、系统 WidgetKit 调度与正式安装仍依赖相应运行环境。
