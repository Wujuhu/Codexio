# 额度查询的连接复用与退避

Mac／Windows 开发版保持 0.3.12。账户和额度通过 Codex app-server 的正常 JSON-RPC 连接读取；仅由 Codexio 主程序持有自有子进程，退出时清理，不另建常驻服务。

## 错误与连接生命周期

临时远端错误、查询超时和解析失败不等于 stdio 断开，不能因此关闭仍可用的 app-server。只有进程退出、输出流关闭、写管道失败、明确切换 Codex 路径或应用退出时，才清理对应自有连接。旧连接在重新创建前释放；Mac 的旧读取回调带连接身份，不能使新连接失效。

失败后的自动重试使用单调时钟。等待时间从 `max(60 秒, 配置刷新间隔)` 开始，每次翻倍，最多 15 分钟；60 秒配置对应 60、120、240、480、900 秒。后台通知不绕过错误退避；业务窗口和重置券的到期仍通过已有展示投影失效，不借此发起额外 RPC，也不更新上次成功获取时间。退避期间暂存的通知不会在稍后被误标为刚获取的结果。手动刷新可以请求存活后端，但新的后端启动仍受冷却限制。

一次连接尝试只初始化一个已通过 CLI 能力探测的候选。初始化失败不因网络错误立即再启动另外三个候选；进程异常退出后的启动也有独立冷却。账户或配置确实改变时继续处理身份失效与刷新，不将旧账户的缓存当作新账户数据。

账户／配置辅助进程还通过自身的命令行覆盖关闭 plugins、remote_plugin、plugin_discovery_prefetch 和 apps。这些功能不用于额度和配置 RPC，无需在辅助进程中初始化其目录；覆盖仅作用于 Codexio 创建的进程，不改用户配置文件和正常 Codex 客户端。启动后的模型刷新仍由 Codex 自身管理，不能仅凭这些参数宣称所有初始化下载均已消除。

这修复了旧 Windows 实现及 `v0.2.10:src/codexio/worker.py` 中“任意查询失败 → 关闭连接 → 短间隔重试”的行为。连接复用沿用当前 Mac 对存活后端的处理；协议仍遵守官方[每个连接仅初始化一次的生命周期](https://learn.chatgpt.com/docs/app-server)。没有通过修改用户 Codex 配置或禁用其插件来规避故障。

## 模型调用计时

普通 Codex rollout 的 token_usage_record 不保证提供逐调用计时。0.3.12 的“上游与计时检测”复用主程序已有的 Responses 转发器，默认仍关闭；开启后沿用原有路由确认、恢复和用户选择重开客户端的流程，不自动启用自定义 OTel。已有上游检测设置保留。

对于经过转发的后续响应，每个连接按真实 response.id 跟踪 response.created 至终态。优先保存响应明确提供的耗时；否则使用两个事件在本机传输层的接收时间和单调时钟计算流式响应耗时。它覆盖 created 到完成的观察区间，不包含 created 之前的连接／排队时间；不是整个用户任务耗时。WebSocket 连接上的多个响应独立关联。一个读取块内的事件共用接收时刻，不把解析队列耗时当作模型耗时。普通 JSON 缺少两端事件时，不用收到整个 JSON 的时间补造开始时间。

TTFT 只保存响应中的明确字段：既有毫秒／秒字段，以及 Codex 响应 timing_metrics 内的 engine_service_ttft_total_ms／engine_iapi_ttft_total_ms。未提供时保持长横杠，不从完整消息、输出项完成、文本 delta 或任务总耗时推算。没有完整流式区间时，可保存响应明确提供的 engine_service_total_ms，同时记下来源。字段兼容性已对照本机 Codex 0.166.0-alpha.5.1 二进制中的协议／遥测字段；不同上游仍可能不提供这些字段。

模型和计时在非界面线程写入数据目录中长期保留的 upstream.sqlite：模型仍使用 observations，计时使用以响应 ID 为主键的 call_timings。这是正式观测账本，不能作为明文／运行缓存删除；Codex 日志被压缩或暂时不可见不删除它。重复完成事件只补缺失证据，不用重放时长覆盖已保存的时长；相同内容不增加 revision。停止转发与正常退出时排空已接受的写入。两端均按观测依赖失效，Windows 继续只标记受影响的调用并按已有有界查询投影，不为计时重扫原始历史。

日志页模型调用、详情及详情中的调用列表共用现有耗时／TPS 和 TTFT 展示。只读取该次调用明确保存的 `duration_ms`，或该次调用的 `call_started_at`／`call_ended_at`；完成计量附带的调用耗时可用于完成调用的输出 TPS，不借用整个用户请求的耗时，不用消息完成时间推算首 Token。

TPS 使用输出 Token 除以该次调用的正数秒数，四舍五入为整数。TTFT 只识别源记录明确提供的毫秒／秒字段，显示两位小数；缺失显示 `—`。计时解释在已有后台快照或有界分页／详情读取中完成，不重采 Token、不修改价格、不为补展示值全量重扫日志。原请求行的紧凑双行布局保持，用时下方显示 TPS，悬停和详情显示 TTFT。

## 本次核验范围

两端继续执行原有三项隔离模拟冒烟。连接错误、超时、恢复、通知退避和启动冷却使用本次一次性假 RPC 子进程核对，不启动真实 Codex，不产生真实 OpenAI 请求，不新增维护性测试套件。真实历史流量证据与代码原因分开记录；不能仅凭进程启动时间对应就断定某个 HTTPS 接口贡献了全部下载，也不能将隔离子进程核验等同于安装新版后的整机流量测量。
