# Go / frontend contract

Binding prefix: `codexio/windows/backend.Service`. Use `@wailsio/runtime` `Call.ByName(prefix + '.' + method, ...args)` behind a single frontend wrapper. All methods return promises; catch errors. Go performs all filesystem/SQLite/network work. Events `codexio:changed` carry `{generation, scope}` and `codexio:notice` carry public status only. Reload only the active page, discard responses issued for previous filters. Do not poll entire UI once per second.

## Public methods (root owns service composition)

- `GetOverview(Query) -> Row`: `{summary, chart, recent, models, comparison, quota, state, generation}`.
- `GetLogs(Query) -> PageResult`: `{rows,total,page,pages,counts}`. Counts keys `requests`, `subagents`, `reviews`, `compactions`, `unassigned`. Page size max100. Modes `user_request`/`model_call`.
- `GetDetails(id: string, page: int) -> Row`: `{request, user, final, attachments, members, composition, page, pages, user_complete, final_complete, availability}`. Full/user/final are source-grounded; keep Markdown safe and support copy.
- Detail responses also include `images` references, with image syntax rewritten to `codexio-image://<id>` in the owning user/final message. Image attachments leave `attachments`; non-image files remain. `GetRequestImage(requestID, imageID) -> Row` resolves only this indexed request's media and returns a bounded `{id,mime,width,height,sha256,dataURL,availability}`. Its Go binding receives a cancellation context; `requestImages.ts` is the specialized reference-counted, two-call bridge wrapper so one unmounted consumer cannot cancel another.
- `GetTrends(Query) -> Row`: `{summary,chart,models,insights,heatmap,activity,chats,chat_page,chat_pages,chat_total,generation}`. `insights.stats` contains local activity/mode statistics; heatmap has 365 prepared daily rows, user counts exclude reviews. Chart/hover uses prepared metrics and never invokes Go. Reading this local view does not fetch account allowance reports.
- `GetChatRanking(metric,page) -> Row`: local lifetime ranking; `metric` is `cost_usd` or `tokens`. Returns at most 25 `threads`, page counts and `data_as_of`. `GetChatRankingDetails(thread) -> Row` loads model/effort/speed `groups` only on expansion. Keep the original table, five-row reveal and detail layout; replace the allowance columns and local-mode switch with cost, Token and a sort picker.
- `GetJourneyCatalog(project,before) -> Row`: `{projects,threads,next}` with at most 50 recent, unarchived top-level threads. An empty project finds the newest thread across all projects. Explicit Codex project assignments win; projectless chats share `chats`, irrespective of their working directories. `before` is the returned opaque cursor.
- `GetJourneyThread(thread,page) -> Row`: `{requests,summary,page,pages}` with at most 25 locally grouped primary requests. Existing continuation/agent ownership is reused, never inferred from matching text.
- `GetJourneyFlow(request,child,cursor) -> Row`: `{events,next}` from indexed turn byte ranges and verified history-base cuts. Empty `child` reads the main journey; an associated child ID reads its scoped turns. Pages contain at most 120 events. Source files are read-only, large result bodies are omitted while retained metadata stays visible, and model prices are overlaid from the existing priced ledger. File stamps include the database WAL where relevant; unchanged log data is cached independently of pricing. No per-tool Token/cost allocation is synthesized. The two-pane view uses project/thread selectors, a request selector, whole-header model disclosure and collapsed command bodies.
- `GetSubscription() -> Row`: quota snapshot plus official reports, cycles/rolling estimate. Quota fields `status`,`updated_at`,`error`,`applicable`,`account`,`plan_type`,`primary`,`secondary`,`credits`,`reports`. Window fields `used_percent`,`remaining_percent`,`window_duration_mins`,`resets_at` (Unix seconds or ISO accepted by formatter). Missing values render `—`, API-key mode explicitly not applicable.
- `GetTrayState() -> Row`: pure quota projection and store status; no official-report request or SQLite aggregation. `Ready() -> void` is called after the main overview has rendered to notify native readiness and acknowledge a verified installed update. `DeferUpdate() -> Row` keeps the existing reminder deferral.
- `GetPrices() -> Row`: `{rows,basis,version,status}`; row base fields `model`,`input`,`cache_read`,`cache_write`,`output`,`service_tier`,`threshold`,`condition`,`source`. USD per million tokens; retain null prices. `SavePrice(model: string,rates: Row) -> Row` modifies only allowed base overrides. `SyncPrices() -> Row` explicitly refreshes the verified price feeds even when automatic synchronization is disabled; conflicts retain the last verified base price.
- `GetReports(period: string) -> Row`: period `day`/`week`/`month`, completed previous natural period. `{period,start,end,date_label,summary,models,time_slices,first,last,previous,style}`. Preserve existing three styles `garden`,`bookmark`,`afternoon`, defaultgarden.
- `GetSettings() -> Row`: public merged preferences + `data_path`,`version`,`mock`,`language`,`mobile`,`upstream`,`update`,`state`. Preserve `theme` light/dark/system, `app_icon`, `codex_roots`, `codex_path`, refreshinterval, reportauto/style, desktop preferences, navigation/column widths, subscriptionprofile.
- `SaveSettings(changes: Row) -> Row`: validated preferences persisted; no direct arbitrary auth/config/file access. Source/model/price changes invalidate relevant backend cache only.
- `Refresh() -> void`, `Rescan() -> void`: asynchronous/coalesced; UI retains existing data with appropriate status.
- `CheckUpdate() -> Row`, `InstallUpdate() -> void`: explicit download/install after user click; progress via scoped events/state. Mock cannot install. Fields `{status,version,notes,progress,error,url}`.
- `ResetCredit(id: string) -> Row`: call only after user selects a concrete card and confirms. Pending unknown result retries same idempotency key, no automatic reset.
- `DesktopAction(action: string) -> void`: `show-main`, `close-main`, `toggle-floating`, `hide-floating`, `quit`, `open-data`, `open-reports`, `show-report`, `restart-client`. Root uses native window/OS APIs and saves final geometry only.
- `OpenURL(url: string) -> void`: explicitly clicked HTTP(S) link in default browser.
- `SaveReportPNG(data: string, period: string) -> Row`: bounded base64PNG, `{path}`; frontend generates the full card, root saves/shares.
- `GetMobile() -> Row`, `MobileAction(action: string, values: Row) -> Row`: `enable`,`disable`,`pair`,`approve`,`deny`,`revoke`,`rename`,`note`,`enroll`,`remove-cloud`,`upload`. Public fields pairing QR/pending/readers/status; no secrets. Pairing up to3readers, ticket5min. Existing read-only protocol.
- `UpstreamAction(enabled: boolean) -> Row`: confirmed user-controlled toggle, `{enabled,desired_enabled,status,error,route_changed,client_running,already_targeted,restart_required}`. Preference persistence follows a successful route transition; mock cannot modify a real route. `restart_required` is true only after an effective route change while a verified desktop client is running.

## Common field meanings

Active request duration follows the union of evidenced execution intervals for the request, continuations and associated non-approval agents. `duration_started_at` is the current real execution anchor and `duration_base_ms` is the completed interval union before that anchor; final `duration_ms` freezes at real terminal records. Missing evidence stays unknown. `duration_active_starts` (zero or one anchor) and `duration_completed_ms` remain compatible. The existing frontend `Duration.svelte` shares one clock among visible, foreground running labels and formats localized hours/minutes/seconds without database reads or ledger publication. Rule changes repair derived groups once; prior `payload.started_at` is recovered through the existing bounded metadata pass without invalidating metering cursors or prices.

Mobile `live.task` and `recent` preserve `started` for the original request date and add stable numeric `durationStarted`/`durationBase` in seconds; `duration` is the final actual execution duration. Fractional Unix seconds survive serialization and retention. Mobile trends use periods `7,30,0` (`0` is complete history), up to 30 recent daily points and 60 older calendar buckets with optional `days`; totals do not truncate history. Request model/effort/speed display normalization is independent of pricing fallbacks.

Windows upstream configuration uses the Mac `config/read` (`includeLayers`) and `config/value/write` (`expectedVersion`) workflow through the existing owned RPC client. The verified user-layer file, profile locator, original value and applied endpoint form the `go-rpc-1` restore journal. Effective-route readback is required after applying a route. Desktop process discovery is only for restart decisions; the CLI binary may live outside the desktop app installation tree. Legacy journals retain their original restore path.

`Query` JSON uses `mode,period,start,end,model,tier,status,search,source,page,page_size,granularity`. Defaultperiod today; start/end local ISO date or timestamp, upperdate inclusive. `source="local"` restricts verified local contributions (reports/activity). Summary uses `usd,tokens,user_requests,input_tokens,cached_input_tokens,cache_hit_rate,unpriced_calls,unpriced_tokens,cost_complete`.

Ledger/group rows preserve original snake-case: `id,timestamp,record_kind,session_title,prompt_preview,output_preview,model,models,reasoning_effort,service_tier,model_context_window,source_ids,request_status,status_label,cost_usd,pricing_status,unpriced_calls,total_tokens,input_tokens,cached_input_tokens,cache_write_input_tokens,output_tokens,duration_ms,call_count,subagent_count,association_note`. Label `automatic_approval_review` as 自动审批审查 / Automatic approval review. It never increases user_request counts or replaces recent true tasks. `context_compaction` is 上下文压缩 / Context compaction. Unknown price remainsnull.

Request ownership also exposes `root_id,root_turn_id,continuation_of,prompt_source_turn_id,resume_kind,started_at,ended_at,status,message_digest,message_revision,is_approval_review`. Only groups with source-confirmed human input contribute to `user_request` counts; explicit continuations share their original request. `context_message` preserves owned accounting whose human input is still unknown and does not contribute to user counts. Mac `approval_review` and guardian source variants normalize to the existing `automatic_approval_review` wire kind. Message digests exclude source recovery signatures/access timestamps. Desktop and mobile share bounded explicit-member message assembly and indexed source recovery; previews are never promoted to complete bodies.

Windows v0.3.7 retains the request-start snapshot mechanism from `v0.2.10:src/codexio/usage_collector.py` (`_turn_activate`) and the current collector: model, effort and speed do not require a metered call. `thread_settings_applied` is pending configuration for the next request, never evidence for an already stopped turn. Explicitly cleared settings cannot retain an earlier Fast tier. At the request boundary, `request_submission.go` also reads Codex's earlier `TurnInput` submission from `logs_*.sqlite`, following the existing read-only SQLite pattern in `readTitles` / `enrichUpstream`. The lookup uses the source's thread/time index, a bounded time window and row/body limits, then verifies the exact turn ID; quoted message text cannot supply settings fields. It captures direct or collaboration-mode model/effort and the explicit speed override, and routes submitted text through the existing ownership, deduplication and bounded message cache. Snapshots remain with the bounded turn state; ordinary unchanged polls do not reread submissions. Metadata version 6 reuses `collector_resume.go`'s bounded recovery for existing records without replaying token accounting. Missing source evidence remains unknown. Request previews never fall back to the mutable thread title. The log and recent-request rows share filter-aware local dates and show only time, effort, accelerated speed and context in the secondary line; Codex model cells retain the requested model below all observed upstream models (deduplicated, sorted and joined with ` + `), with an arrow even when equal; per-call mismatch evidence determines highlighting. Claude model cells retain response IDs with the existing request fallback, and details retain complete observations.

Local chat ranking totals verified local meter costs and tokens for a root thread and explicitly known descendants, including independent accounting records. It uses actual thread names, starts with five rows and caps each requested page at 25 rows. Its user-request count remains independent of those meter totals. The Go implementation reuses `insights.go` session roots and `usage_priced_calls` from the v0.2.10-derived query projection. Mac materializes the same per-thread breakdowns in `LocalChatRanking.swift` when the existing `UsageSnapshotCache` ledger/price/time dependencies change. Process pages reuse Codex `thread_turns` byte offsets and the history-chain mechanism researched for the prototype; no additional collection service or hidden-window polling is introduced.

Mock smoke bridge is separately bound only in mock+smoke mode as `main.SmokeService.Ready({rendered_tokens: string,...})`; root coordinates exactly the original3checks. Do not create frontend test suite, page traversal or screenshot matrix.

Desktop query calls reuse the existing connection pool and projection caches. Wails cancellation contexts and a 30-second read deadline follow SQL reads, recovery and the collector work gate; the frontend has a 35-second fallback and cancels superseded reads. Failed/cancelled row iteration cannot publish cached partial aggregates. Claude source availability is checked once per bounded page. Same-request detail refreshes retain their previous display. Claude pricing resolves only the returned model or its own confirmed alias; it never prices a different returned model using the request model. Pricing-rule changes invalidate existing derived costs without rewriting model IDs or tokens.
