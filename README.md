# AIQuota

Windows 桌面额度与用量面板，通过 Codex `app-server` 读取当前账户额度，并增量扫描会话计量记录，显示：

- 5 小时剩余百分比和重置时间
- 1 周剩余百分比和重置时间
- 最近一次成功更新时间
- 正在读取 / 读取失败 / 数据过期
- 今日、近 7 天、近 30 天及历史 Token 和 API 等价美元
- 小时／天／周用量趋势、逐次请求明细、模型价格和订阅周额度观测估值

可用源码运行，也可以打包成单个 `AIQuota.exe` 发给其他 Windows 用户。0.1.1 起支持从 GitHub 自动下载安装新版，完成后自动重启。

## 环境要求

- Windows 10/11（x64）
- Python 3.9+（计划目标为 3.11+，当前实现兼容 3.9）
- 已安装并完成登录的本机 Codex（`codex.exe` / `codex.cmd`）

程序通过 `account/rateLimits/read` 读取额度，不发起模型请求，也不读取或保存 `auth.json` 中的凭据。用量统计扫描 `sessions` 和 `archived_sessions` 中的计量事件；会话标题、用户消息和模型可见输出的短预览（每段最多 600 字符）保存在本机索引，用于请求列表的悬浮提示。不会保存完整对话或工具输出。

## 启动

在项目根目录执行：

```powershell
.\run.ps1
```

首次运行会创建 `.venv` 并安装依赖。也可以手动启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m aiquota
```

开发预览（不连接真实 Codex）：

```powershell
.\run.ps1 --mock
```

## 使用

- 窗口任意位置左键拖动即可移动；四边或四角拖动即可缩放。点「刷新」立即读取额度，双击窗口也可刷新。
- 拖到屏幕顶部或左右边缘会吸附停靠（顶部横排，两侧竖排），仍可沿边缘挪动，或拖回桌面取消停靠。
- 主界面集中提供概览、用量趋势、请求日志、模型定价、设置。外观、显示模式和刷新间隔在主界面设置页调整。
- 悬浮窗右键可以打开主界面、查看各时间范围的 Token 详情、刷新或关闭悬浮窗。
- 未吸附时显示今日 Token 和美元摘要；吸附到屏幕边缘后只保留原来的额度布局，不显示 Token 或美元。
- 额度样式：条形、圆环、磁贴、紧凑、极简。默认条形、有边框、70% 透明、顶层模式、60 秒刷新；位置和设置会记住。
- 托盘左键打开主界面；右键可以显示／关闭悬浮窗或退出程序。主界面页面按需创建，关闭后释放控件，重新打开保留筛选条件和未保存的设置草稿；托盘、额度读取和后台统计继续运行。
- 主界面可跟随系统或手动选择深浅主题；悬浮窗及托盘右键菜单固定为深色。
- 只更新当前可见页面。悬浮窗只保留正在使用的样式，隐藏时暂停动画和绘制更新，重新显示时使用最新额度与用量。

## Token、价格和请求详情

请求日志默认“按用户请求”展示：同一 Session、同一 Turn 的模型调用和工具往返合并为一行，能够明确关联的子代理调用也计入。每条调用仍按各自模型、档位和价格计算，再合计 Token 与费用。可切换“按模型调用”查看原始调用明细。

用户请求视图的列顺序为：时间、模型、Fast、输入、输出、费用、耗时、Session ID、状态、来源。表格填满页面可用宽度，Fast、状态和来源保持紧凑，其余列均衡分配剩余空间。正常状态显示“完成”或“回复中”；主请求中断显示“已中断”，证据不足显示“未知”。进行中的请求持续更新累计值，部分未定价会明确标注，不把已知小计当作完整费用。

耗时按整轮实际经过时间计算，包含工具等待；已关联子代理并行执行时不重复累加，进行中的请求仅在日志页面可见时刷新计时。模型调用使用日志明确记录的独立计时，缺少完整时间信息的记录显示“—”。历史日志会自动回填可用的耗时信息。

日期按主请求发起日筛选，跨日仍保留整轮费用；模型、来源和档位条件需命中组内同一条调用，显示金额仍为整组累计。普通会话分叉不当作子代理；关联不明确的子代理及无法识别用户轮次的旧调用独立显示。历史轮次元数据会在升级后的首次扫描自动回填，原始调用记录保留。

Session ID 旁的 `!` 可悬停查看会话标题以及最多三行的用户消息及模型可见回复；汇总行使用主请求的预览。请求列表和组成请求的调用明细均从本地数据库按页读取，每页 100 条；双击仍可追查单条调用。界面只保留当前页、趋势汇总和最近一次请求，完整历史及用户请求关联保存在本地数据库。用户与模型消息分别以“用户：”“模型：”区分，不保存完整对话、工具正文或隐藏推理。

首页“最近一次用户请求”放在“近 7 天使用趋势”上方，使用同一份汇总数据，显示状态、调用数、费用、Token 和 Session ID。全局费用及趋势继续按原始调用及实际调用时间统计，不因分组重复累计；相应次数明确标为模型调用。

用量趋势支持按模型筛选，下拉列表只列本机 Codex 提供的模型；未使用过的可用模型也可以选择。首次启动时显示加载进度，首轮用量汇总与额度读取结束后自动收起；空历史和读取错误不会让进度条一直运行。

请求列表的“Fast”列：日志记录 `priority` / `fast` 时显示开启，`default` / `standard` 时显示关闭，缺失或无法识别时显示未知；整轮包含不同档位时显示混合。这是服务速度档位，不是推理强度，也不以单次耗时反推。

趋势默认近 7 天，默认只开启美元和 Token 总数；缓存创建、缓存利用、普通输入和输出可点击图例开启。图表图例、悬浮信息使用 Total Token 与价格字样；底部只显示更新时间。未吸附悬浮窗的摘要格式为 `今日 1.21B Token $80.01`；吸附时只显示额度。

新版 `token_usage_record` 的响应 ID 优先用于去重，旧版 `token_count` 按快照与累计段兼容处理。两种事件同时存在时只统计一次；缓存读写包含在输入中，推理输出包含在输出中。总 Token 为输入加输出。

模型定价页使用美元／百万 Token。自动价格主源为 [LiteLLM](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json)，[models.dev](https://models.dev) 为标准价核验／备用来源；内置官方核验离线快照。默认每 24 小时同步，可立即同步或关闭。支持缓存写入、Fast 与长上下文分档，并保留手工覆盖和价格版本。

定价页面仅列出本机 Codex 模型选择器提供的模型（读取 `models_cache.json`），显示 Standard/Fast 及上下文档位的价格；没有 API 价格的模型显示未定价。页面单价保留两位小数、不显示来源列，内部计算仍保留原始精度。

所有历史金额默认按最新价格重估，表示“这些 Token 按目前 API 价格的等价值”，不是订阅实际扣款。未知模型或不完整价格显示未定价，不当成免费；服务档位缺失时标明按 Standard 估算。

## 周额度等价美元

按同一账号归属、套餐、额度桶和重置周期计算：

```text
满周观测估值 = 同期 API 等价费用 × 100 / 已用额度增加的百分点
剩余观测估值 = 满周观测估值 × 当前剩余百分比 / 100
```

周额度估算按周期缓存；普通刷新只重算发生变化或到达成熟／重置时间边界的周期。迟到日志、价格、账号归属或来源变化会使相关缓存失效，历史记录继续保留。

至少积累 5 个百分点且相关来源、价格完整后才输出估值。达到 100% 后继续完成的请求仍计入消费统计，但不会继续抬高满周估值。额度重置、套餐切换和归属不明的旧日志分开处理；设置中可为已确认的历史时间段指定归属。

界面区分历史观测区间和完整周期记录。未配置的设备、云任务及其他共享额度功能的消费无法由本地日志证明完整，估值始终对应已观测的使用组合，不是 OpenAI 公布的固定周美元预算。`pro` 不自动解释为 `pro20x`。

## 多设备来源

设置中可添加本机 Codex 根目录或 SSH 主机。SSH 复用系统 OpenSSH 配置与认证，远端需要 Python 3，临时运行只读解析并只传回计量元数据及短预览，不安装常驻服务。默认不连接已有主机；首次主机密钥及登录认证需先在系统 SSH 中完成。

本机默认每 5 秒检查新增日志，SSH 每 60 秒同步。局域网发现、共享服务和局域网采集已移除，旧配置中的相关字段会自动忽略，已有统计记录保留。

显示模式：

1. **底层模式**：尽量保持在普通窗口下方。
2. **顶层模式**：始终置顶。默认模式，方便第一次找到窗口。
3. **隐藏悬浮窗**：从托盘或主界面切换显示状态，后台统计继续运行。旧版托盘模式会迁移为此状态。

刷新间隔可选 30 秒、60 秒、5 分钟，默认 60 秒。若收到 `account/rateLimits/updated` 通知，会立即更新。请求失败时按 2、4、8… 秒退避，最长 5 分钟。

## 配置与日志

为兼容旧版设置与历史统计，AIQuota 继续使用原有的配置和缓存目录：

```text
%LOCALAPPDATA%\AIQuotaWidget
```

- `settings.json`：刷新间隔、显示模式、额度样式、窗口位置和大小、背景透明度、边框、可选 Codex 路径
- `quota_cache.json`：最近一次成功额度快照（不含凭据）
- `analytics_settings.json`：主题、统计来源、价格同步、历史归属及悬浮窗显示状态
- `usage.sqlite`：Token、额度观测、会话标题和短输入预览的本机增量索引
- `prices\`：当前模型价格、手工覆盖及历史价格版本
- `logs\aiquota.log`：运行日志。日志会脱敏，不会写入 access token 等认证内容

如需指定 Codex 路径，可在 `settings.json` 写入 `codex_path`，或设置环境变量 `CODEX_CLI_PATH`。

无需 npm 安装 Codex CLI；只安装并登录 Codex App 也可获取额度。程序依次检查设置路径、`CODEX_CLI_PATH`、PATH、App 常见安装目录、Windows 安装登记及正在运行的组件。支持 App 的哈希版本目录、Microsoft Store/MSIX 安装以及自定义安装位置；每次重新连接都会重新查找，App 升级后不会固定使用旧版本路径。优先直接启动经过校验的原生组件，减少 cmd/Node 中转进程；原生组件不可用时仍保留启动脚本回退。

候选组件会先检查 CLI 身份及 `app-server --listen` 支持，排除桌面界面主程序、损坏文件与不兼容版本；实际连接初始化失败时继续尝试其他组件。手动填写的旧版本路径失效时，也会尝试同安装目录中的新版。只在相关安装目录内做有界查找，不扫描整个磁盘。

## 打包成 EXE

`dist` 始终只保留 `AIQuota.exe` 一个可执行文件。构建先暂存到 `build/release-staging`，成功后统一发布；旧包放在 `build/release-backups`，不再保留 `dist/update`、`dist/refined` 等多版本目录。若目标正在运行，先退出小组件再重试发布。

在已经能用 `.\run.ps1` 跑起来的电脑上执行：

```powershell
.\build_exe.ps1
```

构建前请先退出正在运行的旧版小组件。完成后得到 `dist\AIQuota.exe`。把这个文件复制到其他 Windows 10/11（x64）电脑即可双击使用。

对方电脑仍需：

1. 已安装并登录 Codex（小组件只读本机 Codex 额度，不会自带账号）
2. 如本机用了代理访问 ChatGPT，对方也需要能访问 `chatgpt.com`

配置写在每个用户自己的 `%LOCALAPPDATA%\AIQuotaWidget`，不写进 EXE。

## 自动更新与发布

更新源固定为 [Wujuhu/AIQuota](https://github.com/Wujuhu/AIQuota)。EXE 启动 5 秒后检查新版，运行期间每 6 小时检查一次；默认自动下载、校验、安装并重启。可在“设置 → 应用更新”关闭自动更新，或从设置及托盘点击“检查并更新”。源码和 `--mock` 预览模式不自动安装更新。

客户端下载 Release 附件 `latest.json`，避免公共 API 限流。仅接受固定仓库对应版本的 HTTPS 下载地址，并校验文件大小、SHA-256 和 Windows 程序头。发布者身份依赖 GitHub 仓库与 HTTPS，当前未使用独立的发布签名。客户端不需要 GitHub 令牌。

下载成功后，独立更新程序先验证文件和目标目录可写性，再等待 AIQuota 保存设置、停止后台工作并正常退出；随后原位替换 EXE 并自动启动。文件占用时不会结束其他进程。新版启动失败时恢复并启动旧版。更新暂存及最近两份备份保存在 `%LOCALAPPDATA%\AIQuotaWidget\updates`，配置和用量数据库沿用原目录。

首次发布前安装并登录 GitHub CLI（安装后重新打开 PowerShell）：

```powershell
winget install --id GitHub.cli -e
gh auth login --hostname github.com --web
```

发布当前已验证的 0.1.3 包：

```powershell
.\publish_release.ps1 -Version 0.1.3 -SkipBuild -Notes "按用户请求汇总费用，增加状态列并优化紧凑布局"
```

以后修改代码后，一条命令构建并发布新版本：

```powershell
.\publish_release.ps1 -Version 0.1.4 -Notes "填写本次更新说明"
```

脚本会检查登录和版本号、运行测试、构建 EXE、生成更新清单、上传草稿、核验 GitHub 附件哈希，最后发布为 Latest。首次使用空仓库时自动添加发布用 README；本地源码和个人配置不上传。失败的草稿可用同一条命令重试，已发布版本不会被覆盖。应用与 Windows 文件属性统一读取 `src/aiquota/__init__.py` 的版本号。

不使用 GitHub CLI 时，可先准备附件：

```powershell
.\publish_release.ps1 -Version 0.1.3 -SkipBuild -PrepareOnly
```

本次交付的两个文件位于 `build/github-releases/0.1.3`。将 `AIQuota.exe` 和 `latest.json` 一起上传到标签为 `v0.1.3` 的正式 Release，附件全部上传后再发布并设为 Latest。空仓库需先在 GitHub 创建一个 README。以后增加版本号前须经用户明确确认，再使用递增的三段版本号，例如 `0.1.4`；不使用预发布标签。每次 EXE 变化都必须重新生成清单。

旧版 0.1.0 需要手动换上一次 0.1.1 或更高版本，此后即可自动更新。

## 故障排查

**窗口没有出现**  
查看托盘区是否有 AIQuota 图标。单击托盘图标打开主界面，再勾选“显示悬浮窗”。

**提示未找到 Codex**  
确认 `codex --version` 能在终端运行。常见位置：

- `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`
- `%LOCALAPPDATA%\OpenAI\Codex\bin\codex.exe`
- `%USERPROFILE%\.local\bin\codex.cmd`

必要时把完整路径写入 `%LOCALAPPDATA%\AIQuotaWidget\settings.json` 的 `codex_path`。

**提示未登录 / authentication required**  
先在终端执行 `codex login` 或打开 Codex 应用完成 ChatGPT 登录，再刷新小组件。

**额度显示 N/A**  
只有窗口时长约为 300 分钟（5 小时）和 10080 分钟（1 周）时才会映射。缺失或不认识的窗口会显示 `N/A`，不会编造数据。

**提示无法连接 ChatGPT / 网络或代理异常**  
Codex 需要访问 ChatGPT 后端才能读额度。若系统代理指向 `127.0.0.1:7890` 一类本地端口但代理软件未启动，小组件会先尝试直连；直连仍失败时再按退避重试。也可以启动代理，或关闭无效的系统代理。

**读取失败或数据过期**  
查看 `%LOCALAPPDATA%\AIQuotaWidget\logs\aiquota.log`。程序会自动重启异常退出的 `app-server`；网络波动时会退避重试。

**退出后仍有 Codex 进程**  
正常退出应由 Job Object 或进程树清理结束 `codex app-server`。若仍残留，可在任务管理器结束对应 `codex` 进程，并把日志一并保留以便排查。

主界面会员额度中间显示各窗口重置时间；右侧分别显示可用重置次数与整周额度估值。重置次数来自 Codex 的 availableCount，仅展示，不会执行重置。滚动条已加宽并提高拖动区域和对比度。

首页隐藏滚动条，仍可用滚轮浏览底部内容。图表预览以彩色圆点与字段颜色区分 Token、价格及分项。估值记录明确区分“额度重置时间”和“采样时间段”；无估值显示破折号，具体原因由简短状态与悬停说明提供。
