# Codexio

当前本地开发版本为 **0.2.10**。本阶段完成修改、验证和 Mac 开发打包后提交到本地 Git；推送和 GitHub 发布需另行明确授权。

Windows / macOS 桌面额度与用量面板，通过 Codex `app-server` 读取当前账户额度，并增量扫描会话计量记录，显示：

- 5 小时剩余百分比和重置时间
- 1 周剩余百分比和重置时间
- 最近一次成功更新时间
- 正在读取 / 读取失败 / 数据过期
- 今日、近 7 天、近 30 天及历史 Token 和 美元费用
- 小时／天／周用量趋势、逐次请求明细、模型价格和订阅周额度观测估值

可用源码运行。Windows 打包成单个 `Codexio.exe`，保留原有自动更新流程；macOS 打包为 `Codexio.app`，通过 GitHub Release 的 APP ZIP 与统一清单自动更新。

- 上游检测可接管 ChatGPT、OpenAI API 和自定义 Responses provider，只临时改写当前有效 `base_url`；认证字段原样保留，恢复记录不再复制整份配置。

## 上游检测（默认关闭）

Windows 和 macOS 均可在 **设置 → 应用 → 上游检测** 手动开启。当前有效的 ChatGPT、OpenAI API 或自定义 Responses provider 只会把 `base_url` 临时改为带随机令牌的本机回环地址；provider ID、API Key 环境变量、认证命令、固定／环境请求头和查询参数保持原样，不改动 `auth.json` 或系统钥匙串。

- 先应用检测设置或恢复当前模型服务配置，再根据客户端状态提示“稍后自行重启”“现在重启”。Codex 桌面客户端未运行时不提示，也不主动打开它。
- 开启时选择稍后重启，期间客户端没有重启就又关闭检测，配置恢复成客户端原有状态，因此这次关闭不再提示。是否需要重启按客户端进程与已加载的路由判断。
- 上游检测开启时退出 Codexio，会先恢复配置并停止代理，再提示重启；选择任一按钮都会继续退出。关闭状态下退出不提示。
- 保留开启偏好时，下次启动 Codexio 自动应用检测设置，再提示重启；选择后进入主界面。移除旧的开启确认框和退出提示开关。
- 关闭或退出后不保留纯转发进程。选择稍后自行重启的用户，可能需要自行重启 Codex 客户端才能恢复请求。Codexio 自更新使用短暂的服务交接，避免重复切换路由。
- 日志模型上方显示实际响应的型号，折线箭头指向它；响应与对应请求型号不同则文字和箭头标绿，其他情况保持紫色。历史已检测数据保留，不用请求型号冒充检测结果。

详情见 [上游检测实现与验证](docs/upstream-detection.md)。

## macOS

Mac 端要求 macOS 15 或更新系统，复用 Windows 主界面与计价、去重、请求分组和历史统计逻辑，保留概览、日志、用量、订阅、定价、设置六个页面，使用 Mac 系统字体与原生窗口标题栏。此端不创建悬浮窗。

- 点击菜单栏的 Codexio 图标，仅展开 253 px 宽的紧凑预览；可在设置中调整为 293 px。只有点击“主界面”或“设置”才打开相应窗口。
- 预览显示 5 小时／每周额度、剩余百分比、当地重置时间与倒计时，以及今日 美元费用、今日 Token 总数、最近一轮用户请求的累计费用与最多三行用户消息。消息预先过滤系统／环境上下文和附件路径，只有图片时显示“未记录用户文字”。回复中的请求会持续更新；部分未定价、读取失败、缓存与跨日等待均有明确状态。
- 预览最顶部的“主界面”按钮可打开主窗口，底部保留设置和退出。费用和 Token 卡片左右并排；采用 macOS 默认系统字体与较小字号，卡片之间保留 12 px 间距。点击外部区域或按 Esc 收起预览；关闭主窗口后仍继续采集。
- 设置的“应用”页支持自动更新开关和“检查并更新”；Mac 使用同一 GitHub Release 中的 `Codexio.app.zip` 与统一的 `latest.json` 中的 `macos` 部分，下载校验后自动重启安装，源码与模拟模式不安装更新。
- 设置支持主题、额度刷新间隔、预览尺寸与额度范围、启动时是否显示主界面、日志来源列、Codex 路径、本机／SSH 数据来源、模型定价与订阅资料。
- 支持 ⌘K 搜索、⌘, 设置、⌘R 刷新、⌘W 关闭窗口、⌘Q 退出；重复启动会打开已有实例。
- 自动发现 `/Applications`、`~/Applications` 下的 `Codex.app` 和 `ChatGPT.app` 内置 CLI，以及 Homebrew、常见 CLI 安装路径。也可在设置中指定 `.app` 或 CLI 路径。
- Dock 与界面图标直接使用 SVG 原稿，打包时按每个目标尺寸生成 16–1024 px 的 ICNS 资源。
- 日志表格的水平滚动条常驻；其余滚动条仅在滚动时显示，停止滚动 3 秒后隐藏，内容宽度保持稳定。
- 默认数据目录为 `~/Library/Application Support/Codexio`。读取 Codex 本机日志，写入独立的 Codexio 索引；模拟预览使用独立目录。
- 原生 WidgetKit 桌面小组件提供小、中、大三种尺寸，显示进行中的主请求或最近一次请求、估算费用和时长；较大尺寸增加 Token、缓存信息。中、大组件追加 Fast 与实际上下文，最小组件不追加。ChatGPT 模式继续显示 5 小时和周额度；API／自定义 provider 模式完全移除额度区。新快照内容产生后立即向系统申请刷新，主程序与退出后的后台服务使用同一规则；macOS 决定实际显示时机。将 APP 放到“应用程序”并至少启动一次后，可在桌面右键“编辑小组件”中搜索 Codexio。普通 APP 更新保持小组件标识，设计为无需手动重新添加。

开发需要 Python 3.12 或 3.13。首次运行自动创建项目内 `.venv` 并安装依赖：

```bash
./run_macos.sh                 # 读取真实本机用量
./run_macos.sh --mock          # 独立模拟数据预览
./build_macos.sh               # 构建、验证开发 APP 和 APP ZIP，仅写入 build
open build/dev/macos/Codexio.app
```

日常构建仅写入 `build`。开发包通过原生界面检查、签名和 ZIP 解压校验后放入 `build/dev/macos/`，包含可直接打开的 `Codexio.app`、用于传输的 `Codexio.app.zip` 和清单。目录结构为：

```text
build/
├── dev/          # macos 与 windows 的最新开发包
├── staging/      # 构建和上传暂存文件
├── cache/        # PyInstaller 与图标缓存
├── checks/       # 测试、截图和更新流程验证结果
├── logs/         # 构建与测试日志
├── backups/      # 替换开发包时的临时备份
└── tools/        # 本地临时工具
```

只有在用户完成开发验收并第二次明确确认发布及版本号后，执行以下命令；它会核验本地 Mac 包、推送 `main`、创建空正文草稿、触发 Windows x64 构建、发布固定三附件，并在发布后下载复核到本地正式目录：

```bash
.venv/bin/python scripts/publish_release_from_macos.py --version <确认的版本号> --confirm-publish
```

正式目录结构为：

```text
release/
└── <确认的版本号>/
    ├── Codexio.exe
    ├── Codexio.app.zip
    └── latest.json
```

归档要求两端版本、文件大小和 SHA-256 一致；ZIP 内的 APP 版本也必须一致。Windows 工作流失败时 Release 保持草稿，绝不公开残缺版本。已有正式目录、Tag 和正式 Release 不自动覆盖，历史发布保持原样；`build_exe.ps1` 与 `scripts/prepare_release.py` 仍可用于本地故障排查，但不是 0.2.10 的正式发布入口。

Mac 包按构建机器架构生成，目前在 Apple Silicon 上验证，使用本地 ad-hoc 签名。ZIP 解压后是完整的 `Codexio.app`，无需 DMG；建议用 Finder 将 APP 放入 `/Applications` 后运行。更新会等待正常退出、原位替换并启动新版，收到新进程的启动确认后删除旧 APP；启动失败则回滚。旧的 DMG 更新器无法识别新的 ZIP 地址，已安装旧版的用户需要手动更换一次支持 ZIP 更新的 APP。详细说明见 [macOS 开发说明](docs/macos.md)。

## Windows 环境要求

- Windows 10/11（x64）
- 本地开发与打包使用 Python 3.13.15（64 位）。现有 PySide6 6.9 依赖支持 Python 3.9–3.13，暂不支持 3.14。
- 已安装并完成登录的本机 Codex（`codex.exe` / `codex.cmd`）

程序先通过 `account/read` 识别 ChatGPT、API Key 或自定义 provider；只有 ChatGPT 模式才调用 `account/rateLimits/read`。额度读取不发起模型请求，也不保存 `auth.json` 中的凭据。用量统计扫描 `sessions` 和 `archived_sessions` 中的计量事件；会话标题、用户消息和模型可见输出的短预览（每段最多 600 字符）保存在本机索引，用于请求详情。不会保存完整对话或工具输出。


```powershell
py -3.13 -m venv .venv
```

## 使用

- 窗口任意位置左键拖动即可移动；四边或四角拖动即可缩放。点「刷新」立即读取额度，双击窗口也可刷新。
- 拖到屏幕顶部或左右边缘会吸附停靠（顶部横排，两侧竖排），仍可沿边缘挪动，或拖回桌面取消停靠。
- 主界面默认依次为概览、请求日志、用量趋势、订阅额度、模型定价、设置。旧偏好首次载入时采用这个顺序；之后仍支持拖动、右键上移／下移或 Alt + 方向键调整，顺序自动保存，概览固定第一。
- 悬浮窗右键可以打开主界面、查看各时间范围的 Token 详情、刷新或关闭悬浮窗。
- 未吸附时显示今日 Token 和美元摘要；吸附到屏幕边缘后只保留原来的额度布局，不显示 Token 或美元。
- 额度样式：条形、圆环、磁贴、紧凑、极简、光球。默认条形、有边框、70% 透明、顶层模式、60 秒刷新；位置和设置会记住。设置按外观、悬浮窗、数据来源和应用分组，所有设置修改后自动保存并应用；路径、颜色等输入项在结束编辑时保存。
- 托盘左键打开主界面；右键可以显示／关闭悬浮窗或退出程序。主界面页面按需创建，关闭后释放控件，重新打开保留筛选条件和设置分组；托盘、额度读取和后台统计继续运行。
- 主界面可跟随系统或手动选择深浅主题；悬浮窗及托盘右键菜单固定为深色。
- 主界面以中性底色搭配清晰的浅色数据标记：价格为珊瑚红，Token 为薄荷绿；Token 构成用紫、蓝、黄区分缓存读取、普通输入和输出，有缓存写入时增加粉色。分段条与图例颜色一致。
- 首页两个额度条与 Token 分段条使用相近的厚度和圆角，随剩余额度从浅绿连续过渡到浅黄、浅红；未知额度保持中性空条。
- 只更新当前可见页面。悬浮窗只保留正在使用的样式，隐藏时暂停动画和绘制更新，重新显示时使用最新额度与用量。

## Token、价格和请求详情

请求日志默认“按用户请求”展示：同一 Session、同一 Turn 的模型调用和工具往返合并为一行，能够明确关联的子代理调用也计入。每条调用仍按各自模型、档位和价格计算，再合计 Token 与费用。可切换“按模型调用”查看原始调用明细。

“来源”列默认隐藏，可在“设置 → 外观 → 请求日志 → 显示来源列”勾选后自动保存并显示，两种日志模式共用此设置。隐藏列不会删除来源信息或停用来源筛选。

用户请求视图依次显示：用户输入与发起时间、模型、输入／输出、缓存命中率、费用、耗时、状态、来源、详情；表头和内容统一居中，窄窗口可横向滚动查看完整数值。时间说明采用 `9.2 17:00 · 1 次调用 · Fast`；Standard 不显示档位，按模型调用则只显示时间和非 Standard 档位，不再显示调用 ID。多模型单独显示实际模型数量。正常状态显示“完成”或“回复中”，“回复中”采用鲜艳绿色与较大粗体；主请求中断显示“已中断”，证据不足显示“未知”。进行中的请求持续更新累计值，部分未定价会明确标注，不把已知小计当作完整费用。

耗时按整轮实际经过时间计算，包含工具等待；已关联子代理并行执行时不重复累加，进行中的请求仅在日志页面可见时刷新计时。模型调用使用日志明确记录的独立计时，缺少完整时间信息的记录显示“—”。历史日志会自动回填可用的耗时信息。

日期按主请求发起日筛选，跨日仍保留整轮费用；模型、来源和档位条件需命中组内同一条调用，显示金额仍为整组累计。普通会话分叉不当作子代理；关联不明确的子代理及无法识别用户轮次的旧调用独立显示。历史轮次元数据会在升级后的首次扫描自动回填，原始调用记录保留。

请求表格与翻页控件位于统一的圆角画布内，筛选保留在上方。“按用户请求”最右侧为超链接样式的“详情”，悬停可打开 320 px 宽的浮窗，支持滚动和复制；离开链接和浮窗后自动关闭。右侧固定预览、首次默认展开以及日志页其他悬浮提示已移除。“按模型调用”不增加详情列。浮窗保留会话标题、用户消息、费用及 Token 汇总、回复、标识符和调用组成。请求列表每页 100 条，完整历史及用户请求关联保存在本地数据库，不保存完整对话或工具正文。

输入预览先按文本块过滤插件清单、AGENTS 与环境等自动上下文，插件引用简化为 `@Impeccable` 等名称，图片统一在问题末尾显示为 `[image] x N`。截断长问题时仍保留图片数量；同一附件的文字标记与图片内容不重复计数。新解析器首次运行时会回填旧预览，保持原始响应 ID、Token 和计价不变；模型记录的输入 Token 仍包含实际送入模型的上下文。

概览顶部的五小时额度、周额度和 Token 构成各占三分之一宽度，标签与各自百分比成对排布。额度条在剩余至少 75% 时使用明亮薄荷绿，下降后平滑经过黄色到低额度红色。概览、趋势和请求日志的时间筛选默认“今日”，手动选择或明确指定的日期继续保留。今日、近 7 天、近 30 天、全部切换同时作用于用量摘要、整幅趋势图和最近请求；点击图表日期可进入对应日志。全局费用及趋势继续按原始调用及实际调用时间统计，不因分组重复累计；相应次数明确标为模型调用。

订阅额度页集中显示当前额度、可用主动重置次数和每次截止时间。周额度估算记录按每页 10 条分页展示，本地最多保留最近 100 条有效记录；表格显示套餐、采样时间段、额度变化、总 Token、已计价费用和周估值。只有接口明确返回日期才显示截止日期，明确无期限与缺少日期分别标注；总次数采用接口总数，不用已返回明细条数替代。个人套餐、订阅价格及续费日期可手动记录，未填写的数据不推断，编辑资料不改变实际订阅。

用量趋势支持按模型筛选，下拉列表只列本机 Codex 提供的模型；未使用过的可用模型也可以选择。首次启动时显示加载进度，首轮用量汇总与额度读取结束后自动收起；空历史和读取错误不会让进度条一直运行。

用量页的每日 Token 热力图呈现近一年的记录，并跟随当前模型筛选。方格按当地日期排列，悬停查看当天 Token、调用记录数和费用，点击可进入对应日期及模型的调用日志。无记录日期显示“暂无记录”，缺失价格仍显示“未定价”；日历不包含未来活动。

请求列表的档位移至用户消息下方的时间说明：`priority` / `fast` 追加 Fast，`default` / `standard` 不追加档位；缺失或空值默认 Standard，同样省略，并纳入 Standard 筛选与整轮分组；无法识别的非空档位仍显示“未记录”；整轮包含不同档位时显示 Mixed。Mixed 可筛选用户请求，按模型调用时禁用；切换模式会保留各自的档位选择。这是服务速度档位，不是推理强度，也不以单次耗时反推。原始日志的空值保持不变；按默认档位计价的依据保留在详情中。

概览和用量页的四项汇总为费用、Total Token、用户请求数、缓存命中率。用户请求数按主请求发起时间去重统计，关联子代理不另计，未归属调用不计为用户请求；已记录用户输入但尚无模型计量的请求仍计入。费用与 Token 则继续按调用计量时间汇总，跨午夜时两种时间口径可能不同。模型筛选下只统计包含该模型调用的主请求。

缓存命中率为缓存读取 Token ÷ 输入 Token（包含缓存部分），缓存创建不计为命中；整轮和汇总按 Token 加权，缺失或异常分项不按零处理。日志页不再显示 Token/s 列。


首页的趋势图同时显示 API 费用和 Token，左侧为 Token 刻度、右侧为美元刻度。两条线采用清晰的浅色细线和轻填充；同时显示时，Token 轴增加上方余量，使 Token 线通常靠下，价格按正常比例显示，允许真实数据产生重叠。两轴均从零开始，刻度和悬停数值保持真实；单独查看 Token 时恢复正常缩放。用量趋势默认今日、按小时展示，默认开启美元和 Token 总数；缓存创建、缓存利用、普通输入和输出可点击图例开启。图表图例、悬浮信息使用 Total Token 与价格字样；底部只显示更新时间。未吸附悬浮窗的摘要格式为 `今日 1.21B Token $80.01`；吸附时只显示额度。

概览的费用、Token、调用数卡片仅显示标题、数值和区间变化，说明放在悬浮提示中。百分比也显示在用量趋势图下方：今日比较昨天全天，近 7 天比较本期起点之前完整的 7 天，近 30 天比较之前完整的 30 天，不截断到当前时刻。上涨用绿色与向上箭头，下降用红色与向下箭头；用量页的模型筛选同时作用于两期。两期按指标分别过滤和汇总：Token 使用可确认的总数并校验已有输入、输出分项；费用只累加有效的已定价或参考估值；调用数使用已有去重结果，仅计可确认的独立调用，不能证明响应身份的累计观测或增量不计为一次调用。时间不明的记录不参与，价格未知不影响已确认的 Token 和调用数。

用量趋势在今日、近 7 天、近 30 天、全部和自选日期下均显示 费用、Total Token 与模型调用汇总，并遵循日期及模型筛选。自选日期包含起止日期全天；全部和自选日期只显示汇总，不显示周期对比。日期反选或没有有效数据时显示“—”，不保留上次范围的数值。预设周期的卡片数值直接使用比较中的本期合计。两期都有有效数据且前期非零时显示百分比；任一期无有效数据时显示“暂无对比”，对应未知卡片数值显示“—”；前期为零、本期非零时显示“前期为 0”，两期都为已确认的零时显示 0.0%。跳过记录时，悬浮提示注明“按已确认数据计算”。采集未完整不再全局阻断对比，原始日志、历史数据库、诊断信息及周额度估算等其他完整性规则保持原有口径。比较只读取对应日期范围，并在可见页面刷新时计算。图表也跳过无法确认的 Token 和无效金额，只有无效值的时间点保留未知状态，避免异常记录阻止页面刷新。

自选日期使用统一日期选择器，趋势、日志与历史计量归属保持相同布局；弹出日历完整显示六周日期，支持翻月和键盘选日。订阅额度页将当前资料、额度、主动重置明细和周期记录按顺序放在同一滚动页面，不再切换“当前额度／周期记录”分页。

折线的已知数据节点常驻显示，缺失价格处保留断点；悬停时放大当前节点并显示引导线。文字预览在日期下方按“价格 → Total Token → 请求数”排列，再列出已开启的 Token 分项。

新版 `token_usage_record` 的响应 ID 优先用于去重，旧版 `token_count` 按快照与累计段兼容处理。两种事件同时存在时只统计一次；缓存读写包含在输入中，推理输出包含在输出中。总 Token 为输入加输出。

模型定价页使用美元／百万 Token。自动价格主源为 [LiteLLM](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json)，[models.dev](https://models.dev) 为标准价核验／备用来源；内置官方核验离线快照。只同步 Standard、普通上下文的 API 基础价，默认每 24 小时同步，可立即同步或关闭。Fast 与长上下文换算价由应用的 Codex 规则统一生成，上游 API 的加速价和长文价不会覆盖这些规则。手工编辑只作用于基础价，随后更新该模型的全部换算行。

定价页面仅列出本机 Codex 模型选择器提供的模型（读取 `models_cache.json`）。同一张表只显示 Standard、Fast 及适用的上下文条件，不再单列 API 基准。普通 Standard 使用 OpenAI 官方 API 标准单价，整行六列加粗；缺失单价或没有明确规则的组合保留未定价。六列表头和内容统一居中、等宽分配；窄窗口保留横向滚动，长文本和倍率可查看完整提示。

所有本地费用展示共用同一计价后端，覆盖日志、调用组成、概览、趋势、悬浮窗摘要及本地周额度参考值。普通 Standard 直接采用 OpenAI API 的输入、缓存读取、缓存创建和输出标准价；已使用但未公布单价的类别保留未定价。Fast 和长上下文继续沿用既有 Codex 规则：Fast 对 Astra、GPT-5.6、GPT-5.5 使用 2.5 倍，对 GPT-5.4 使用 2 倍；GPT-5.6／5.5／5.4 输入超过 272K 时，输入与缓存读取再乘 2、输出再乘 1.5；Astra 不加长文倍率。这些换算条件中的缓存创建按普通输入价计入。金额是应用定义的 API 等价值，不是实际账单、订阅扣款或官方 credits。价格或规则版本变化后，历史金额与汇总缓存自动重算；未知模型、缺失价格或不支持的档位不当成免费，服务档位缺失时的估计依据保留在详情中。公式、边界和来源见 [计价规则](docs/codex-pricing.md)。

所有美元金额和单价统一显示小数点后两位，包含日志、详情、图表坐标与悬浮提示、订阅资料、周额度估值和悬浮窗。小额已知值按两位小数舍入，未知值仍显示未定价或空状态；计算和存储保留原始精度，不按已舍入的逐条显示值汇总。编辑价格或订阅资料时，未改动的字段也保留原值。

左侧导航使用“概览、日志、用量、订阅、定价、设置”，页面标题保留完整名称。Windows 系统标题栏的背景和文字随应用深浅主题切换，新建窗口及重新显示时也会同步。

应用品牌为 Codexio，采用用户提供的 Quantum "X" Core 标志。主界面左上角名称使用 Times New Roman，文字相对原位置向左、向下微调。SVG、PNG、多尺寸 ICO 和横向品牌组合见 [品牌资源](docs/branding/codexio/README.md)。

## 周额度等价美元

v0.2.8 的周额度估算只对本机主日志来源的模型调用与当前账号的周额度样本配对。设置 → 应用可选择 10、30、60 分钟估算周期，默认 10 分钟；额度按独立设置继续刷新，每个成功样本用于识别账号、套餐或重置变化。账号身份只保存摘要值，不保存原始账号 ID。算法为：

```text
周费用估值 = 同期已计价费用 × 100 / 已用周额度增加的百分点
```

样本至少等待两分钟供日志计量写入。10／30／60 分钟窗口的周额度没有增加时，不生成记录；对应费用和总 Token 随起点一起顺延到下一有效窗口，Token 只用于表格展示，不进入周美元估值公式。若套餐、账号、额度池或重置周期切换，或取样中断太久，该窗口作废并重新开始。未能确认账号、调用价格缺失时不生成估值；有多个额度池却无法确认调用归属时也不生成。只有接口明确显示唯一 Codex 额度池时，才把未标额度池的本机调用计入该池。

历史记录重新定价时，最近 100 条估算会依据本机调用重新计算。升级时清理旧的周期估算缓存和额度观测表，原始模型调用台账仍用于日志、趋势与重新定价；SQLite 已分配的文件页可能由后续写入复用。

其他设备、云任务及共享额度功能的消费无法由本机日志证明完整。短窗口估值始终是已观测使用组合的美元等价推算，不是 OpenAI 公布的固定周美元预算。`pro` 不自动解释为 `pro20x`。

## 多设备来源

设置中可添加本机 Codex 根目录或 SSH 主机。SSH 复用系统 OpenSSH 配置与认证，远端需要 Python 3，临时运行只读解析并只传回计量元数据及短预览，不安装常驻服务。默认不连接已有主机；首次主机密钥及登录认证需先在系统 SSH 中完成。

本机默认每 10 秒检查新增日志，可在设置的应用页选择 5 秒、10 秒、30 秒或 1 分钟。旧版自动保存的 5 秒默认值会迁移为 10 秒，此后手动选择 5 秒会保留。正常增量扫描先检查文件元数据，只读取发生变化的日志；首次建索引、手动重扫或解析规则变化时会读取所需历史。用量内容变化时更新显示，日期等时间边界仍会定期更新。SSH 每 60 秒同步。局域网发现、共享服务和局域网采集已移除，旧配置中的相关字段会自动忽略，已有统计记录保留。

显示模式：

1. **底层模式**：尽量保持在普通窗口下方。
2. **顶层模式**：始终置顶。默认模式，方便第一次找到窗口。
3. **隐藏悬浮窗**：从托盘或主界面切换显示状态，后台统计继续运行。旧版托盘模式会迁移为此状态。

刷新间隔可选 30 秒、60 秒、5 分钟，默认 60 秒。若收到 `account/rateLimits/updated` 通知，会立即更新。请求失败时按 2、4、8… 秒退避，最长 5 分钟。

## 配置与日志

新安装使用以下配置和缓存目录；已有安装会自动沿用 `%LOCALAPPDATA%\AIQuotaWidget` 或 `%LOCALAPPDATA%\AIQuota` 中的现有数据：

```text
%LOCALAPPDATA%\Codexio
```

- `settings.json`：刷新间隔、显示模式、额度样式、窗口位置和大小、背景透明度、边框、可选 Codex 路径
- `quota_cache.json`：最近一次成功额度快照（不含凭据）
- `analytics_settings.json`：主题、统计来源、价格同步、历史归属及悬浮窗显示状态
- `usage.sqlite`：Token、额度观测、会话标题和短输入预览的本机增量索引
- `prices\`：当前模型价格、手工覆盖及历史价格版本
- `logs\codexio.log`：运行日志。日志会脱敏，不会写入 access token 等认证内容

如需指定 Codex 路径，可在 `settings.json` 写入 `codex_path`，或设置环境变量 `CODEX_CLI_PATH`。

无需 npm 安装 Codex CLI；只安装并登录 Codex App 也可获取额度。程序依次检查设置路径、`CODEX_CLI_PATH`、PATH、App 常见安装目录、Windows 安装登记及正在运行的组件。支持 App 的哈希版本目录、Microsoft Store/MSIX 安装以及自定义安装位置；每次重新连接都会重新查找，App 升级后不会固定使用旧版本路径。优先直接启动经过校验的原生组件，减少 cmd/Node 中转进程；原生组件不可用时仍保留启动脚本回退。

候选组件会先检查 CLI 身份及 `app-server --listen` 支持，排除桌面界面主程序、损坏文件与不兼容版本；实际连接初始化失败时继续尝试其他组件。手动填写的旧版本路径失效时，也会尝试同安装目录中的新版。只在相关安装目录内做有界查找，不扫描整个磁盘。

## 打包成 EXE

正式 `Codexio.exe` 在用户确认发布后由 GitHub Actions 的 Windows x64 runner 构建并直接加入草稿 Release。本地 `build_exe.ps1` 保留作 Windows 故障排查：输出仍在 `build/dev/windows/`，暂存在 `build/staging/windows`，同版本旧 EXE 暂存在 `build/backups/windows`；它不会自行发布。

在已经能用 `.\run.ps1` 跑起来的电脑上执行：

```powershell
.\build_exe.ps1
```

对方电脑仍需：

1. 已安装 Codex，并已完成 ChatGPT／API Key 登录或配置好自定义 Responses provider
2. 能访问其当前模型服务；Codexio 不自带账号或 API Key

配置写在每个用户自己的 `%LOCALAPPDATA%\Codexio`，不写进 EXE。

## 自动更新与发布

更新源固定为 [Wujuhu/Codexio](https://github.com/Wujuhu/Codexio)。EXE 启动 5 秒后检查新版，运行期间每 6 小时检查一次；默认自动下载、校验、安装并重启。可在“设置 → 应用更新”关闭自动更新，或从设置及托盘点击“检查并更新”。源码和 `--mock` 预览模式不自动安装更新。

Windows 与 Mac 共用 Release 附件 `latest.json`：顶层字段保持 Windows 旧格式，`macos` 部分记录 Mac 的 APP ZIP 信息，避免公共 API 限流。仅接受固定仓库对应版本的 HTTPS 下载地址，并校验文件大小、SHA-256 和 Windows 程序头。发布者身份依赖 GitHub 仓库与 HTTPS，当前未使用独立的发布签名。客户端不需要 GitHub 令牌。

下载成功后，独立更新程序先验证文件和目标目录可写性，再等待 Codexio 保存设置、停止后台工作并正常退出；随后原位替换 EXE 并自动启动。文件占用时不会结束其他进程。新版启动失败时恢复并启动旧版。更新暂存及最近两份备份保存在 `%LOCALAPPDATA%\Codexio\updates`，配置和用量数据库沿用原目录。

首次发布前在 Mac 安装并登录 GitHub CLI：

```bash
brew install gh
gh auth login --hostname github.com --web
```

日常只构建并验收 Mac 开发包。只有用户第二次明确确认发布版本后，才执行：

```bash
.venv/bin/python scripts/publish_release_from_macos.py \
  --version <确认的版本号> \
  --confirm-publish
```

协调脚本核验 Mac APP、签名、ZIP 和清单后推送 `main`，创建空正文草稿并显式触发 Windows 工作流。工作流从同一提交构建 EXE、合并清单并验证两端版本、下载地址、文件大小与 SHA-256；缺少任一安装包或清单不匹配时保持草稿。三个文件全部通过后才转为正式 Release，随后脚本自动下载同一组附件复核并创建本地 `release/<版本号>/`。

Tag 与标题均为 `v<版本号>`，正文留空，新 Tag 基于远程 `main`；已有正式 Tag、Release 或本地正式目录不覆盖。失败草稿只能对同一版本和提交显式使用 `--resume-draft` 继续；远程成功而本地归档缺失时可用 `--sync-only` 补齐。增加版本号与正式发布都须分别取得明确确认。应用与 Windows 文件属性统一读取 `src/codexio/__init__.py` 的版本号。

旧版 0.1.0 需要手动换上一次 0.1.1 或更高版本，此后即可自动更新。

## 最小运行检查

原测试套件和专项测试脚本已移除。仅保留三个基本冒烟检查：程序能启动、基本数据显示正常、主窗口能关闭并重新打开。Mac 开发打包会自动执行一次；Windows 可通过 `run.ps1 --mock` 确认基本运行。版本、签名、ZIP 和哈希仍按交付流程核验。

后续不新增测试文件或测试项，不运行全量回归、界面遍历和截图矩阵。具体约束见 [项目要求](AGENTS.md)。

## 故障排查

**窗口没有出现**  
查看托盘区是否有 Codexio 图标。单击托盘图标打开主界面，再勾选“显示悬浮窗”。

**提示未找到 Codex**  
确认 `codex --version` 能在终端运行。常见位置：

- `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`
- `%LOCALAPPDATA%\OpenAI\Codex\bin\codex.exe`
- `%USERPROFILE%\.local\bin\codex.cmd`

必要时把完整路径写入 `%LOCALAPPDATA%\Codexio\settings.json` 的 `codex_path`。

**提示未登录 / authentication required**  
先在终端执行 `codex login` 或打开 Codex 应用完成 ChatGPT 登录，再刷新小组件。

**额度显示 N/A**  
只有窗口时长约为 300 分钟（5 小时）和 10080 分钟（1 周）时才会映射。缺失或不认识的窗口会显示 `N/A`，不会编造数据。

**提示无法连接 ChatGPT / 网络或代理异常**  
Codex 需要访问 ChatGPT 后端才能读额度。若系统代理指向 `127.0.0.1:7890` 一类本地端口但代理软件未启动，小组件会先尝试直连；直连仍失败时再按退避重试。也可以启动代理，或关闭无效的系统代理。

**读取失败或数据过期**  
查看 `%LOCALAPPDATA%\Codexio\logs\codexio.log`。程序会自动重启异常退出的 `app-server`；网络波动时会退避重试。

**退出后仍有 Codex 进程**  
正常退出应由 Job Object 或进程树清理结束 `codex app-server`。若仍残留，可在任务管理器结束对应 `codex` 进程，并把日志一并保留以便排查。

概览、订阅额度、周期记录和悬浮窗的重置日期后统一显示星期，例如“9月16日 周三 16:03”；主动重置截止日期也显示星期，窄悬浮窗按需换行。订阅仪表盘使用更饱满的半圆、较粗线条及较大文字，周期估值右侧的说明文字已移除。主动重置次数来自 Codex 的 availableCount，仅展示，不会执行重置。

各页及请求预览的滚动条仅在滚动期间显示，停止 3 秒后隐藏；拖动时保持可见。隐藏时保留正文宽度与拖动区域，避免内容跳动。请求预览的会话标题使用 20 px 半粗体，与用户正文区分；切换主题后保持相同层级。图表预览以彩色圆点与字段颜色区分 Token、价格及分项。估值记录明确区分“额度重置时间”和“采样时间段”；无估值显示破折号，具体原因由简短状态与悬停说明提供。
